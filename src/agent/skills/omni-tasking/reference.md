# 任务生成规则（参考）

主流程见 [SKILL.md](SKILL.md)。本文件定义任务格式与组织规则，生成 tasks.md 时严格遵循。

## 关键原则

- 任务按**用户故事**组织，以支持独立实现与测试。
- **测试任务**：仅当功能规范明确要求测试或用户要求 TDD 时才生成。

## 检查清单格式（必需）

每任务严格遵循：

```text
- [ ] [TaskID] [P?] [Story?] 带文件路径的描述
```

**格式组件**

1. **复选框**：以 `- [ ]` 开头
2. **任务 ID**：按执行顺序 T001、T002、T003…
3. **[P]**：仅当任务可并行时（不同文件、不依赖未完成任务）
4. **[Story]**：仅用户故事阶段需要，格式 [US1]、[US2]…；设置/基础阶段无故事标签；完善阶段无故事标签
5. **描述**：含确切文件路径的清晰操作

**示例**

- ✅ `- [ ] T001 根据实施计划创建项目结构`
- ✅ `- [ ] T005 [P] 在 src/middleware/auth.py 中实现认证中间件`
- ✅ `- [ ] T012 [P] [US1] 在 src/models/user.py 中创建用户模型`
- ❌ `- [ ] 创建用户模型`（缺 ID/故事标签）
- ❌ `- [ ] T001 [US1] 创建模型`（缺文件路径）

## 任务组织

1. **来自用户故事 (spec.md)**：每个故事 P1、P2、P3… 单独阶段；将模型、服务、端点、故事专属测试映射到该故事；标出故事依赖（多数故事应独立）。
2. **来自合约**：每个合约/端点映射到其服务的用户故事；若要求测试，在该故事阶段实现前插入合约测试任务 [P]。
3. **来自数据模型**：实体映射到所需故事；若实体服务多故事，放在最早的故事或设置阶段；关系放在对应故事阶段的服务层任务。
4. **来自设置/基础设施**：共享基础设施→阶段 1；基础/阻塞任务→阶段 2；故事特定设置→该故事阶段内。

## 阶段结构

- **阶段 1**：设置（项目初始化）
- **阶段 2**：基础（阻塞先决条件，必须在用户故事之前完成）
- **阶段 3+**：按优先级顺序的用户故事（P1、P2、P3…）；每故事内：测试（若请求）→ 模型 → 服务 → 端点 → 集成；每阶段为可独立测试的增量。
- **最终阶段**：完善与横切关注点
