# 阶段 7：分析系统上下文

## 输入内容
`omni-doc/specs-temp/intermediate/scenario-overview.md`

**输入文件格式说明**：
- 输入文件为Markdown格式，包含"场景列表"概要表格和"场景详情"段落
- 每个场景详情包含：场景ID（格式为 `SCN-XXX`）、场景名称、描述、关联功能、时序图
- 需要从场景描述中识别所有外部系统，并分析系统间的交互关系

## 步骤

### 第一步：理解输入内容
仔细阅读输入内容，关注：
- 所有的场景描述
- 场景的业务目的和处理内容
- 场景时序图中涉及的参与者
- 识别场景中涉及的所有外部系统（时序图中标注的外部参与者）

### 第二步：识别外部系统
从场景描述和时序图中提取所有外部系统：
- 识别上游系统（调用本系统的系统）
- 识别下游系统（本系统调用的系统）
- 识别其他相关系统（如：用户、第三方系统等）
- 总结每个外部系统与本系统的交互方式（REST API、事件回调、消息通信等）
- 明确每个外部系统的职责和业务角色

### 第三步：分析系统关系
分析本系统与各个外部系统的关系：
- **上游系统关系**：明确上游系统如何调用本系统（接口类型、调用方式、业务目的）
- **下游系统关系**：明确本系统如何调用下游系统（接口类型、调用方式、业务目的）
- **数据流向**：识别数据在系统间的流向（请求数据、响应数据、事件数据等）
- **依赖关系**：识别系统间的依赖关系（本系统依赖哪些外部系统，哪些外部系统依赖本系统）

### 第四步：撰写系统上下文描述
编写系统上下文的概述性描述：
- **系统定位和职责**：说明本系统的核心职责和主要功能
- **系统在整体架构中的位置**：说明本系统在整个系统架构中的位置和作用
- **与外部系统的交互关系概述**：概括本系统与外部系统的主要交互方式

### 第五步：绘制系统上下文图
使用PlantUML的C4 Context图表示系统上下文：
- 使用 `!include <C4/C4_Context>` 引入C4 Context图库
- 使用 `System` 表示本系统
- 使用 `System_Ext` 表示外部系统
- 使用 `Person` 表示用户（如适用）
- 使用 `Rel` 表示系统间的关系，标注交互内容和协议/技术
- 设置合适的布局方向（建议使用 `left to right direction`）

### 第六步：编写系统说明
按模板要求详细说明每个系统：
- **当前系统**：系统名称、系统职责、系统定位
- **外部系统列表**：逐个描述每个外部系统（系统名称、系统类型、系统职责、交互关系）

### 第七步：编写交互关系说明
逐条详细说明系统间的交互关系：
- **交互双方**：明确哪两个系统之间的交互
- **交互内容**：说明交互的具体内容
- **交互方向**：单向/双向
- **协议/技术**：使用的协议或技术
- **交互场景**：在什么场景下进行交互

### 第八步：补充可选章节
根据场景分析结果，酌情补充以下可选章节（有则写，无则省略）：
- **协议与技术栈**：列出系统间交互使用的协议和技术
- **系统边界**：说明系统的职责范围
- **约束与假设**：说明系统的运行环境和前提条件

### 第九步：整理输出
读取模板文件 `specify/metamodel/2.context-template.md`，严格按照模板结构生成输出文件：
- 存放到 `omni-doc/specs/context.md`
- 确保 YAML frontmatter 中所有字段填写完整（name, version, description）
- 确保输出格式符合Markdown规范

### 第十步：DoD 校验
生成文档后，执行以下校验，全部通过方可结束本阶段：

1. **外部系统全覆盖**：从 `scenario-overview.md` 的时序图中提取所有外部参与者，确认每个均在上下文图和"外部系统列表"中出现
2. **Frontmatter 完整性**：`name`、`version`、`description` 字段均非空
3. **章节结构**：对照模板 `specify/metamodel/2.context-template.md`，确认必选章节全部存在
4. **PlantUML 语法**：上下文图代码块有 `plantuml` 语言标识，包含 `!include <C4/C4_Context>`，且无明显语法错误（如缺少 `@enduml`）
5. **交互关系完整**：每个外部系统至少有一条 `Rel` 关系描述，且"交互关系说明"章节中有对应条目
6. **系统说明完整**：当前系统和每个外部系统均有名称、职责描述

如果发现问题，就地修复后重新校验，直到全部通过。

## 分析要点
- **完整性**：确保所有场景中涉及的外部系统都已识别，不遗漏任何系统
- **准确性**：系统关系的描述必须基于场景描述，不能主观推测
- **清晰性**：系统上下文图应该清晰展示系统边界和系统间的交互关系
- **层次性**：区分上游系统（调用方）和下游系统（被调用方），明确数据流向
- **交互方式**：准确标注系统间的交互方式（REST API、事件机制、消息通信等）

## 输出格式

读取模板文件 `specify/metamodel/2.context-template.md`，严格按照模板结构生成输出文件。

### 输出要求
- **输出路径**：`omni-doc/specs/context.md`
- **模板遵循**：文件结构、frontmatter 字段、章节层级均以模板文件为准
- **填充规则**：
  - frontmatter 中所有字段必须填写完整（name, version, description）
  - 使用 C4_Context 图描述系统上下文
  - 系统说明和交互关系说明必须详细完整
  - 可选章节有则写、无则省略

**注意事项**：
- 使用 `!include <C4/C4_Context>` 而非 `C4_Container`
- 系统标识使用简洁的驼峰命名
- 交互关系使用 `Rel(系统A, 系统B, "交互内容", "协议")` 格式
- 外部系统类型应明确（上游/下游/第三方等）
