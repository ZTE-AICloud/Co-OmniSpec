# 阶段 2b：批量生成实体规范

## 任务目标
对 `omni-doc/specs-temp/intermediate/entity-overview.md` 文件中的每个实体条目，逐个深入分析代码并生成符合实体模板的独立规范文件。

## 执行流程

### 步骤1：准备工作
1. 读取子提示词文件：当前 skill 目录下的 `phase-2b-entity-specs-unit.md`
2. 读取实体概览文件：`omni-doc/specs-temp/intermediate/entity-overview.md`
3. 读取或创建进度文件：`omni-doc/specs-temp/task_process.md`（格式见下方）
4. 确保输出目录存在：`omni-doc/specs/entities/`

### 步骤2：批量分析执行
按照**实体ID升序**（ENTITY-001 → ENTITY-002 → ENTITY-003...）依次处理实体概览文件中的每个实体条目：

1. **跳过已完成项**：检查进度文件中"实体规范生成进度"部分对应项的状态，若为 `[x]` 则跳过
2. **构造分析任务**：
   - 从实体概览文件中提取当前实体的完整信息（实体ID、实体名称、实体描述、属性列表、方法列表、关联接口）
   - 将实体信息整理为文本格式，替换子提示词模板中的 `{{entity_info}}` 占位符
   - 执行子提示词模板中定义的分析步骤
3. **验证输出**：确认实体规范文件已正确生成到 `omni-doc/specs/entities/` 目录
4. **更新进度**：完成一个实体的分析后，立即更新进度文件，将对应项标记为 `[x]`
5. **Token计数**：每完成一个实体的分析，累计本次会话的Token消耗（输入Token + 输出Token）

### 步骤3：Token超限处理
- **监控阈值**：当本次会话累计Token数达到 **100,000** 时暂停
- **暂停提示**：提示用户："已生成 X 个实体规范，累计消耗约 100k tokens。请在新会话中重新执行此命令继续后续生成。"
- **恢复机制**：用户在新会话中重新执行此命令时，系统自动从进度文件中读取状态，跳过已标记 `[x]` 的实体，继续处理未完成项

## 进度文件格式

文件路径：`omni-doc/specs-temp/task_process.md`

在现有进度文件中添加或更新以下部分：

```markdown
## 实体规范生成进度
- [ ] ENTITY-001
- [ ] ENTITY-002
- [ ] ENTITY-003
...
```

### 状态标记说明
- `[ ]` - 未开始
- `[x]` - 已完成
- `[-]` - 进行中（可选，用于标识当前正在处理的项）

### 使用规则
1. **自动跳过**：每次执行任务时，自动跳过所有状态为 `[x]` 的项
2. **即时更新**：每完成一个实体的规范生成，立即将该项状态更新为 `[x]`
3. **幂等性保证**：即使多次执行，已完成的项不会被重复处理

### 步骤4：批量完成 DoD 校验
所有实体处理完毕（或进度文件中全部标记为 `[x]`）后，执行以下校验：

1. **覆盖率检查**：从 `entity-overview.md` 的"实体列表"表格中提取所有 `ENTITY-XXX` ID，逐一验证 `omni-doc/specs/entities/` 目录下存在对应的 `ENTITY-XXX-*.md` 文件。列出缺失项（如有）
2. **Frontmatter 完整性**：抽样读取 3-5 个已生成的规范文件，检查 frontmatter 必填字段（id, name, layer, description）均非空
3. **文件命名一致性**：抽样检查文件名中的 ID 与 frontmatter 中的 `id` 字段一致
4. **PlantUML 类图存在性**：抽样检查 3-5 个规范文件，确认包含 `plantuml` 代码块

如果发现缺失项，自动重新执行子提示词补生成对应实体。校验全部通过后，向用户报告完成状态和覆盖率。

## 注意事项
1. 本阶段仅处理"实体规范生成进度"部分，其他进度段供后续阶段使用
2. 执行过程中无需用户确认，按顺序自动批量处理
3. 实体条目从 `entity-overview.md` 的"实体详情"部分提取，每个实体包含：实体ID、实体名称、实体描述、属性列表、方法列表等信息
4. 严格按照实体ID数字顺序处理（ENTITY-001 → ENTITY-002 → ...）
5. 输出文件命名格式：`ENTITY-XXX-实体名称.md`，其中 `XXX` 为实体ID中的数字
6. Token计数应包含完整的输入和输出，建议每5-10个实体检查一次累计值
