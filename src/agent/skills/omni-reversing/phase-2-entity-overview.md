# 阶段 2：批量分析逻辑实体

## 任务目标
对 `omni-doc/specs-temp/intermediate/interface-overview.md` 文件中的每个接口条目，逐个分析其涉及的数据结构和方法，提取并整理为逻辑实体，输出到 `omni-doc/specs-temp/intermediate/entity-overview.md`。

## 执行流程

### 步骤1：准备工作
1. 读取子提示词文件：当前 skill 目录下的 `phase-2-entity-overview-unit.md`
2. 读取接口概览文件：`omni-doc/specs-temp/intermediate/interface-overview.md`
3. 读取或创建进度文件：`omni-doc/specs-temp/task_process.md`（格式见下方）

### 步骤2：批量分析执行
按照**接口ID升序**（API-001 → API-002 → API-003...）依次处理接口概览文件中的每个接口条目：

1. **跳过已完成项**：检查进度文件中对应项的状态，若为 `[x]` 则跳过
2. **构造分析任务**：
   - 从接口概览文件中提取当前接口的完整信息（接口ID、接口名称、接口描述、入口标识、所在文件、代码映射）
   - 将接口信息整理为文本格式，替换模板中的 `{{interface_info}}` 占位符
   - 执行模板中定义的分析步骤
3. **更新进度**：完成一个接口的分析后，立即更新进度文件，将对应项标记为 `[x]`
4. **Token计数**：每完成一个接口的分析，累计本次会话的Token消耗（输入Token + 输出Token）

### 步骤3：Token超限处理
- **监控阈值**：当本次会话累计Token数达到 **100,000** 时暂停
- **暂停提示**：提示用户："已分析 X 个接口，累计消耗约 100k tokens。请在新会话中重新执行此命令继续后续分析。"
- **恢复机制**：用户在新会话中重新执行此命令时，系统自动从进度文件中读取状态，跳过已标记 `[x]` 的接口，继续处理未完成项

## 进度文件格式

文件路径：`omni-doc/specs-temp/task_process.md`

```markdown
# 任务执行进度跟踪

## 逻辑实体分析进度
- [ ] API-001
- [ ] API-002
- [ ] API-003
...

## 功能分析进度
（预留给阶段3使用）
- [ ] API-001
...

## 时序图生成进度
（预留给阶段5使用）
- [ ] API-001
...
```

### 状态标记说明
- `[ ]` - 未开始
- `[x]` - 已完成
- `[-]` - 进行中（可选，用于标识当前正在处理的项）

### 使用规则
1. **自动跳过**：每次执行任务时，自动跳过所有状态为 `[x]` 的项
2. **即时更新**：每完成一个接口的逻辑实体分析，立即将该项状态更新为 `[x]`
3. **幂等性保证**：即使多次执行，已完成的项不会被重复处理

### 步骤4：概览 DoD 校验
所有接口处理完毕（或进度文件中"逻辑实体分析进度"全部标记为 `[x]`）后，对 `entity-overview.md` 执行以下校验，全部通过方可结束本阶段：

1. **ID 唯一性**：所有 `ENTITY-XXX` ID 无重复
2. **ID 连续性**：ID 序列基本连续（允许少量跳号，不应大段缺失）
3. **实体列表字段完整性**：表格每行的 4 个字段（实体ID、实体名称、实体描述、关联接口）均非空
4. **详情段落覆盖**："实体列表"表格中的每个 ENTITY-ID，在"实体详情"部分都有对应的三级标题段落
5. **详情结构完整**：抽样检查 3-5 个实体详情段落，确认包含"描述"、"属性"表格、"方法"表格
6. **统计一致性**："实体统计"中的实体总数与"实体列表"表格的实际行数一致
7. **接口概览回填**：抽样检查 `interface-overview.md` 中 3-5 个接口行，确认"逻辑实体"列已填写

如果发现问题，就地修复后重新校验，直到全部通过。

## 注意事项
1. 本阶段仅处理"逻辑实体分析进度"部分，其他进度段供后续阶段使用
2. 执行过程中无需用户确认，按顺序自动批量处理
3. 接口条目从 `interface-overview.md` 文件的表格中提取，每个接口包含：接口ID、接口名称、接口描述、入口标识、所在文件、代码映射等信息
4. 严格按照接口ID数字顺序处理（API-001 → API-002 → ... → API-110）
5. 接口信息格式化为文本时，应包含所有字段，以便模板中的分析步骤能够正确执行
6. Token计数应包含完整的输入和输出，建议每5-10个接口检查一次累计值
