# 任务: 生成单个功能规范

## 输入内容
{{function_info}}

## 步骤

### 第一步：定位功能代码
- 根据**输入内容**中的关联接口和关联实体信息，定位功能涉及的源代码
- 阅读接口概览中对应接口的代码映射，找到功能的处理入口
- 阅读泳道活动图中涉及的实体对应的代码

### 第二步：完善功能描述
- 基于代码分析，完善功能的业务背景描述
- 明确功能的处理逻辑和预期结果
- 识别功能的输入数据和输出数据

### 第三步：细化主流程活动图
- 在输入内容已有泳道活动图的基础上，补充细节
- 确保活动图以逻辑实体作为泳道，体现实体间的流转
- 使用业务语言描述步骤，不出现代码元素
- 添加关键的条件分支和判断逻辑
- 确保 PlantUML 语法正确，可正常渲染

### 第四步：识别异常流程（可选）
- 检查代码中的错误处理和异常分支
- 如有明显的异常流程，绘制异常流程活动图
- 如果异常处理较简单，可在异常场景章节文字描述

### 第五步：提取关键步骤说明
- 识别主流程中需要补充说明的关键步骤
- 对每个关键步骤说明：处理逻辑、校验规则、数据转换等细节
- 这些细节是活动图中难以表达的补充信息

### 第六步：明确输入输出
- 识别功能的输入数据（报文、消息、配置等）及其类型和来源
- 识别功能的输出数据（响应报文、状态更新、统计信息等）及其类型和去向

### 第七步：整理并输出
按照**输出格式**要求，将结果保存到 `omni-doc/specs/functions/FUNC-XXX-功能名称.md`

- 文件名中的 `XXX` 与功能ID一致
- 文件名中的功能名称与功能名称一致
- 确保 YAML frontmatter 中所有字段填写完整
- 确保输出格式符合Markdown规范

## 输出格式

读取模板文件 `specify/metamodel/5.function-template.md`，严格按照模板结构生成输出文件。

### 输出要求
- **输出路径**：`omni-doc/specs/functions/FUNC-XXX-功能名称.md`
- **模板遵循**：文件结构、frontmatter 字段、章节层级均以模板文件为准
- **填充规则**：
  - 将分析步骤中提取的信息填充到模板对应位置
  - frontmatter 中所有字段必须填写完整（id, name, description, inputs, outputs）
  - 主流程必须包含 PlantUML 泳道活动图
  - 关键步骤说明须逐项展开
  - 可选章节（异常流程、异常场景、性能要求、约束条件）如当前阶段信息不足，可标注"待后续阶段补充"

**注意事项**：
- **分析必须基于代码实际内容**，不能主观推测
- 活动图中的描述使用业务语言，不出现代码元素（变量名、函数名等）
- frontmatter 中的 `description` 为一句话简要描述，详细描述放在正文"功能"章节中
- 泳道标注格式：`|实体名称\nENTITY-XXX|`（实体名称和实体ID分行显示）
