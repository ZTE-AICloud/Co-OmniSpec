# 任务: 生成单个场景规范

## 输入内容
{{scenario_info}}

## 步骤

### 第一步：理解场景上下文
- 根据**输入内容**中的场景描述和关联功能，理解场景的业务背景
- 阅读关联功能的详细文档（`omni-doc/specs/functions/FUNC-XXX-*.md`），深入理解功能的处理流程

### 第二步：完善场景描述
基于功能文档分析，完善场景的详细描述：
- **业务背景**：场景在系统中的定位和价值
- **触发条件**：什么情况下触发该场景
- **主要参与者**：涉及的外部系统、内部模块、逻辑实体
- **预期结果**：场景执行完成后的预期状态或输出

### 第三步：细化时序图
在输入内容已有时序图的基础上，补充细节：
- 参与者使用逻辑实体标注（格式：`实体名称\nENTITY-XXX`）
- 使用 `== 流程名称 ==` 分隔不同的子流程
- 补充关键的条件分支（alt/else/end）
- 补充异常处理流程
- 确保 PlantUML 语法正确，可正常渲染

### 第四步：编写验收场景
基于场景的业务逻辑，编写 Given-When-Then 格式的验收场景：
- **Given**：描述初始状态/前置条件
- **When**：描述触发操作
- **Then**：描述预期结果
- 覆盖主要的正常流程和关键异常流程
- 每个场景至少包含 2-3 条验收场景

### 第五步：整理并输出
按照**输出格式**要求，将结果保存到 `omni-doc/specs/scenarios/SCN-XXX-场景名称.md`

- 文件名中的 `XXX` 与场景ID一致
- 文件名中的场景名称与场景名称一致
- 确保 YAML frontmatter 中所有字段填写完整
- 确保输出格式符合Markdown规范

## 输出格式

读取模板文件 `specify/metamodel/3.scenario-template.md`，严格按照模板结构生成输出文件。

### 输出要求
- **输出路径**：`omni-doc/specs/scenarios/SCN-XXX-场景名称.md`
- **模板遵循**：文件结构、frontmatter 字段、章节层级均以模板文件为准
- **填充规则**：
  - 将分析步骤中提取的信息填充到模板对应位置
  - frontmatter 中所有字段必须填写完整（id, name, brief, description）
  - 时序图必须包含 PlantUML 代码块
  - 验收场景必须使用 Given-When-Then 格式

**注意事项**：
- **分析必须基于功能文档的实际内容**，不能主观推测
- 时序图中的参与者标注应使用逻辑实体ID
- frontmatter 中的 `brief` 为一句话简要描述，`description` 为详细描述
- 验收场景应覆盖主要正常流程和关键异常流程
