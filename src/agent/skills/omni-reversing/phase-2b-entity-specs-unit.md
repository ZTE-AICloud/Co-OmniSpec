# 任务: 生成单个实体规范

## 输入内容
{{entity_info}}

## 步骤

### 第一步：定位实体代码
- 根据**输入内容**中的属性和方法信息，定位实体对应的源代码文件
- 阅读数据结构定义（结构体/类/对象）的完整代码
- 阅读关联方法的实现代码

### 第二步：确定实体层次
根据实体的职责和在系统中的位置，判断实体所属层次：
- **ui**: 用户界面层，处理展示和交互
- **application**: 应用层，处理业务流程编排
- **domain**: 领域层，承载核心业务逻辑和规则

### 第三步：完善属性分析
对每个属性深入分析：
- **类型**：确认具体数据类型（结构体类型、基本类型、枚举等）
- **用途**：说明属性的业务用途
- **取值范围**：识别枚举值、数值范围等约束（如有）
- **约束条件**：识别非空、唯一性等约束（如有）

### 第四步：完善方法分析
对每个方法深入分析：
- **函数签名**：提取完整的函数签名（含参数类型和返回值类型）
- **功能描述**：说明方法的主要功能和处理逻辑
- **输入参数**：列举各参数及其含义
- **返回值**：说明返回值类型和含义
- **调用场景**：说明方法在什么业务场景下被调用

### 第五步：撰写职责说明
总结实体的核心职责：
- 主要处理哪些业务逻辑
- 与其他实体的交互关系
- 在系统中的定位和作用

### 第六步：绘制 PlantUML 类图
根据属性和方法信息，绘制实体的 PlantUML 类图：
- 使用 `+` 表示公共成员
- 属性格式：`+ 属性名 : 类型`
- 方法格式：`+ 函数名(参数1:类型, 参数2:类型, ...) : 返回类型`
- 确保语法正确，可正常渲染

### 第七步：整理并输出
按照**输出格式**要求，将结果保存到 `omni-doc/specs/entities/ENTITY-XXX-实体名称.md`

- 文件名中的 `XXX` 与实体ID一致
- 文件名中的实体名称与实体名称一致
- 确保 YAML frontmatter 中所有字段填写完整
- 确保输出格式符合Markdown规范

## 输出格式

读取模板文件 `specify/metamodel/6.entity-template.md`，严格按照模板结构生成输出文件。

### 输出要求
- **输出路径**：`omni-doc/specs/entities/ENTITY-XXX-实体名称.md`
- **模板遵循**：文件结构、frontmatter 字段、章节层级均以模板文件为准
- **填充规则**：
  - 将分析步骤中提取的信息填充到模板对应位置
  - frontmatter 中所有字段必须填写完整（id, layer, name, description）
  - PlantUML 类图必须包含所有属性和方法
  - 属性说明和方法说明须逐项展开

**注意事项**：
- **分析必须基于代码实际内容**，不能主观推测
- 职责说明应从业务视角描述，而非重复代码结构
- frontmatter 中的 `description` 为一句话简要描述，详细描述放在正文"实体"章节中
- layer 的判断应基于实体在代码中的实际位置和职责
