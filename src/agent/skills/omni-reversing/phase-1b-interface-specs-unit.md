# 任务: 生成单个接口规范

## 输入内容
{{interface_info}}

## 步骤

### 第一步：定位接口代码
- 根据**输入内容**中的代码映射信息，找到接口的处理函数/方法
- 根据入口标识，确认接口的触发入口点
- 阅读处理函数的完整实现代码

### 第二步：提取接口定义
- 提取接口的函数签名或入口定义（如函数原型、API路由定义、消息处理注册等）
- 记录函数签名的完整形式，包括参数类型和返回值类型

### 第三步：分析输入参数
- 识别接口接收的所有输入参数
- 对每个参数记录：参数名、参数类型、参数含义
- 如果参数是复合结构（如消息体、请求体），展开说明其关键字段

### 第四步：分析返回值
- 确认接口的返回值类型
- 说明成功/失败场景下的返回值含义
- 如果有错误码，列举主要错误码及其含义

### 第五步：分析处理流程
- 沿着处理函数的调用链，梳理主要处理步骤
- 描述接口的核心处理逻辑（不需要逐行翻译代码，而是提炼业务逻辑）
- 识别关键的分支判断和状态转换

### 第六步：分析调用场景
- 确认接口在什么条件下被触发
- 识别调用者（外部系统/模块）
- 说明调用时机和前置条件

### 第七步：识别异常处理（可选）
- 检查接口中的错误处理逻辑
- 记录主要的异常情况及对应处理方式
- 如果没有明显的异常处理逻辑，此节可省略

### 第八步：识别关联关系（可选）
- 分析接口与其他接口、实体的交互关系
- 如果存在明确的协作关系，记录下来
- 如果关联关系不明显或需要后续阶段补充，此节可省略

### 第九步：整理并输出
按照**输出格式**要求，将结果保存到 `omni-doc/specs/interfaces/API-XXX-接口名称.md`

- 文件名中的 `XXX` 与接口ID一致
- 文件名中的接口名称与接口名称一致
- 确保 YAML frontmatter 中所有字段填写完整
- 确保输出格式符合Markdown规范

## 输出格式

读取模板文件 `specify/metamodel/7.interface-template.md`，严格按照模板结构生成输出文件。

### 输出要求
- **输出路径**：`omni-doc/specs/interfaces/API-XXX-接口名称.md`
- **模板遵循**：文件结构、frontmatter 字段、章节层级均以模板文件为准
- **填充规则**：
  - 将分析步骤中提取的信息填充到模板对应位置
  - frontmatter 中所有字段必须填写完整（id, name, file, identifier, description）
  - 可选章节（关联关系、异常处理）如当前阶段信息不足，可标注"待后续阶段补充"

**注意事项**：
- **分析必须基于代码实际内容**，不能主观推测
- 处理流程描述应提炼业务逻辑，而非逐行翻译代码
- frontmatter 中的 `description` 为一句话简要描述，详细描述放在正文"接口"章节中
- 代码块中的语言标识应与项目实际使用的编程语言一致
