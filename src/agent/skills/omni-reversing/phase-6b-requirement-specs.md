# 阶段 6b：批量生成需求规范

## 任务目标
对 `omni-doc/specs-temp/intermediate/requirement-overview.md` 文件中的每个需求条目，逐个生成符合需求模板的独立规范文件。

## 执行流程

### 步骤1：准备工作
1. 读取子提示词文件：当前 skill 目录下的 `phase-6b-requirement-specs-unit.md`
2. 读取需求概览文件：`omni-doc/specs-temp/intermediate/requirement-overview.md`
3. 读取或创建进度文件：`omni-doc/specs-temp/task_process.md`（格式见下方）
4. 确保输出目录存在：`omni-doc/specs/requirements/`

### 步骤2：批量分析执行
按照**需求ID升序**（REQ-001 → REQ-002 → REQ-003...）依次处理需求概览文件中的每个需求条目：

1. **跳过已完成项**：检查进度文件中"需求规范生成进度"部分对应项的状态，若为 `[x]` 则跳过
2. **构造分析任务**：
   - 从需求概览文件中提取当前需求的完整信息（需求ID、需求名称、需求类型、需求描述、关联场景、EARS描述）
   - 将需求信息整理为文本格式，替换子提示词模板中的 `{{requirement_info}}` 占位符
   - 执行子提示词模板中定义的分析步骤
3. **验证输出**：确认需求规范文件已正确生成到 `omni-doc/specs/requirements/` 目录
4. **更新进度**：完成一个需求的生成后，立即更新进度文件，将对应项标记为 `[x]`
5. **Token计数**：每完成一个需求的生成，累计本次会话的Token消耗

### 步骤3：Token超限处理
- **监控阈值**：当本次会话累计Token数达到 **100,000** 时暂停
- **暂停提示**：提示用户："已生成 X 个需求规范，累计消耗约 100k tokens。请在新会话中重新执行此命令继续后续生成。"
- **恢复机制**：用户在新会话中重新执行此命令时，系统自动从进度文件中读取状态，跳过已标记 `[x]` 的需求，继续处理未完成项

## 进度文件格式

文件路径：`omni-doc/specs-temp/task_process.md`

在现有进度文件中添加或更新以下部分：

```markdown
## 需求规范生成进度
- [ ] REQ-001
- [ ] REQ-002
- [ ] REQ-003
...
```

### 使用规则
1. **自动跳过**：每次执行任务时，自动跳过所有状态为 `[x]` 的项
2. **即时更新**：每完成一个需求的规范生成，立即将该项状态更新为 `[x]`
3. **幂等性保证**：即使多次执行，已完成的项不会被重复处理

### 步骤4：批量完成 DoD 校验
所有需求处理完毕（或进度文件中全部标记为 `[x]`）后，执行以下校验：

1. **覆盖率检查**：从 `requirement-overview.md` 的"需求列表"表格中提取所有 `REQ-XXX` ID，逐一验证 `omni-doc/specs/requirements/` 目录下存在对应的 `REQ-XXX-*.md` 文件。列出缺失项（如有）
2. **Frontmatter 完整性**：抽样读取 3-5 个已生成的规范文件，检查 frontmatter 必填字段（id, name, type, description）均非空
3. **文件命名一致性**：抽样检查文件名中的 ID 与 frontmatter 中的 `id` 字段一致
4. **EARS 内容存在性**：抽样检查 3-5 个规范文件，确认正文包含 EARS 描述内容

如果发现缺失项，自动重新执行子提示词补生成对应需求。校验全部通过后，向用户报告完成状态和覆盖率。

## 注意事项
1. 本阶段仅处理"需求规范生成进度"部分，其他进度段供后续阶段使用
2. 执行过程中无需用户确认，按顺序自动批量处理
3. 需求条目从 `requirement-overview.md` 的"需求详情"部分提取
4. 严格按照需求ID数字顺序处理（REQ-001 → REQ-002 → ...）
5. 输出文件命名格式：`REQ-XXX-需求名称.md`，其中 `XXX` 为需求ID中的数字
