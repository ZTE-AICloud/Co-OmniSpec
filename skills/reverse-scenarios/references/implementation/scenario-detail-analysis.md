# 场景详细分析Skill（默认）

## Overview

这是一个通用的场景详细分析skill，用于分析单个场景的详细信息并生成结构化的场景详细文档。该skill结合LSP工具、代码分析、测试用例提取和业务语义分析等多种方式，能够从源文件中提取场景的完整信息并生成标准化的文档。

## 输入参数

Skill接收以下输入参数：

- **scenario_info** (必需): 场景基本信息对象，包含：
  - `scenario_id`: 场景ID（格式：SCN-XXX）
  - `scenario_name`: 场景名称
  - `business_name`: 业务名称
  - `business_domain`: 业务领域
  - `scenario_type`: 场景类型（如"正向主流程"、"异常场景"等）
  - `priority`: 优先级（high/medium/low）
  - `source_files`: 源文件路径数组（绝对路径）
  - `entry_points`: 入口函数列表（可选）
- **template_path** (必需): 场景详情模板文件路径（绝对路径）
- **output_dir** (必需): 输出目录路径（绝对路径）
- **repo_root** (必需): 仓库根目录路径（绝对路径）

## 输出格式

Skill生成场景详细文档到指定路径，并返回处理结果对象：

**输出文件**：
- 文件路径：`{output_dir}/SCN-XXX-场景名称.md`
- 文件名格式：`SCN-XXX-场景名称.md`，其中 `XXX` 为三位数字，与场景ID中的数字保持一致
- 场景名称应简洁明了，使用中文

**返回结果对象**：
```json
{
  "status": "success" | "failed",
  "scenario_id": "SCN-001",
  "output_file": "{output_dir}/SCN-001-场景名称.md",
  "error_message": null
}
```

**注意**：
- 如果分析失败，`status` 为 `"failed"`，`error_message` 包含详细错误信息
- 如果成功，`status` 为 `"success"`，`error_message` 为 `null`
- `output_file` 始终包含生成的文档路径（即使失败也可能包含部分生成的文件）

## When to Use This Skill

在以下情况下使用此skill：
- 需要分析单个场景的详细信息并生成文档
- 项目没有定制化的场景详细分析需求
- 需要通用的场景详细分析能力

## Workflow

### 步骤1：读取模板文件

1. 读取 `template_path` 指定的场景详情模板文件
2. 验证模板文件是否存在且可访问
3. 解析模板结构，识别需要填充的占位符

### 步骤2：分析场景详细信息

🔴 **强制要求**：必须分析场景的完整信息，包括业务背景、触发条件、主要参与者和预期结果

#### 2.1 场景基本信息提取

- 🔴 **必须提取**：场景ID、场景名称、业务名称、业务领域、场景类型、优先级
- **来源**：从 `scenario_info` 输入参数中直接获取

#### 2.2 场景描述信息提取（必须完整提取）

- 🔴 **必须提取**：
  - **业务背景**：场景发生的业务背景和上下文
  - **触发条件**：场景的触发条件和前置条件
  - **主要参与者**：场景涉及的主要业务实体和角色
  - **预期结果**：场景执行后的预期结果和状态变化
- **分析方法**：
  - 从源文件中读取相关代码和注释
  - 分析测试用例（如果有）了解场景的预期行为
  - 从业务逻辑代码中提取场景流程
  - 使用LSP工具获取函数和类的文档字符串

#### 2.3 验收场景生成（Given/When/Then格式）

- 🔴 **必须提取**：生成至少2-3个验收场景，使用Given/When/Then格式
- **Given**：初始状态和前置条件
- **When**：触发操作或事件
- **Then**：预期结果和验证点
- **分析方法**：
  - 从测试用例中提取验收场景（如果存在）
  - 从业务逻辑代码中推断验收场景
  - 基于场景类型生成标准验收场景

#### 2.4 场景流程信息提取

- 🔴 **必须提取**：
  - **主要步骤**：场景执行的主要步骤和流程
  - **关键决策点**：场景中的关键决策点和分支逻辑
  - **异常处理**：场景中的异常情况和处理方式
- **分析方法**：
  - 分析源文件中的业务逻辑代码
  - 追踪函数调用链了解完整流程
  - 识别条件分支和异常处理逻辑
  - 使用LSP工具精准获取函数调用链

#### 2.5 相关实体和接口识别

- 🔴 **必须提取**：
  - **相关业务实体**：场景涉及的业务实体
  - **相关接口**：场景调用的接口或API
  - **数据流转**：场景中的数据流转和状态变化
- **分析方法**：
  - 从源文件中识别业务实体定义
  - 追踪接口调用关系
  - 分析数据结构和状态变化
  - 使用LSP工具获取类定义和接口信息

#### 2.6 LSP工具使用（如果支持）

- 🔴 **优先使用LSP工具**：在支持LSP的语言中，优先使用LSP工具获取精确的符号信息和定义上下文
  - 使用 `documentSymbol` 识别场景相关的函数和类
  - 使用 `goToDefinition` 获取完整的定义信息
  - 使用 `findReferences` 了解场景的使用场景和调用链
  - 使用 `hover` 获取符号的文档和类型信息
- 🔴 **后备机制**：当LSP工具不可用时，使用文件读取和模式匹配方式分析场景

### 步骤3：填充模板并生成文档

1. **填充模板内容**：
   - 替换场景基本信息占位符（id、name、brief、description）
   - 填充场景详细描述（业务背景、触发条件、主要参与者、预期结果）
   - 生成验收场景（Given/When/Then格式，至少2-3个）
   - 补充场景流程信息（主要步骤、关键决策点、异常处理）
   - 添加相关实体和接口信息

2. 🔴 **生成文档文件**：
   - 生成场景详情文档到 `{output_dir}/SCN-XXX-场景名称.md`
   - 文件名格式：`SCN-XXX-场景名称.md`，其中 `XXX` 为三位数字，与场景ID中的数字保持一致
   - 场景名称应简洁明了，使用中文
   - 确保输出目录存在，如果不存在则创建

3. **验证文档**：
   - 确保生成的文档文件格式正确且已成功创建
   - 验证文档内容完整性
   - 检查模板占位符是否都已填充

### 步骤4：返回处理结果

- 如果成功：返回 `{"status": "success", "scenario_id": "...", "output_file": "...", "error_message": null}`
- 如果失败：返回 `{"status": "failed", "scenario_id": "...", "output_file": "...", "error_message": "详细错误信息"}`

## LSP增强分析支持

### LSP支持的语言

- **Python**: 使用Python Language Server
- **JavaScript/TypeScript**: 使用TypeScript Language Server
- **Java**: 使用Eclipse JDT Language Server
- **Go**: 使用gopls
- **C/C++**: 使用clangd

### LSP工具使用策略

1. **符号精确识别**：
   - 使用 `documentSymbol` 识别文件内的精确符号位置
   - 使用 `workspaceSymbol` 在整个工作区中搜索相关符号
   - 结合符号类型信息过滤出场景相关符号（函数、类、测试用例等）

2. **定义上下文获取**：
   - 使用 `goToDefinition` 获取符号的完整定义上下文
   - 使用 `hover` 获取符号的类型信息和文档
   - 使用 `findReferences` 了解符号的使用场景和调用链

3. **交叉验证机制**：
   - 将LSP识别结果与代码分析结果交叉验证
   - 优先采用LSP提供的精确位置信息
   - 对于LSP无法识别的模式，回退到传统文件读取和模式匹配

### LSP使用要求

- **优先使用**：在支持LSP的语言中，优先使用LSP工具进行精确分析，减少不必要的文件读取
- **Token管理**：使用LSP工具时注意控制查询频率，避免过多的LSP请求消耗资源
- **后备机制**：当LSP工具不可用时，自动回退到传统的文件读取和模式匹配策略，确保处理连续性
- **精确指定**：每次调用LSP工具时必须明确指定文件路径、函数名等精确信息

## Token管理要求

### 核心原则

- 🔴 **强制Token检查点**：
  - 处理每个场景前必须检查当前上下文大小，如超过10万tokens则强制清空
  - 处理完成后必须检查当前上下文大小，如超过15万tokens则报错
- 🔴 **优先使用LSP工具**：使用LSP工具获取结构化信息，避免读取完整文件内容
- 🔴 **精确指定信息**：调用LSP工具时必须明确指定文件路径、函数名等精确信息
- 🔴 **限制文件读取**：大文件只读取场景相关部分及其上下文（上下各50行）

### 具体要求

- **场景描述提取**：优先从文档字符串、注释和测试用例中获取信息，避免分析完整实现代码
- **业务流程识别**：使用LSP工具精准获取函数调用链，避免读取完整函数体
- **业务实体识别**：按需追踪相关类定义，避免加载整个模块
- 🔴 **强制要求：上下文清理**：处理完当前场景后立即清理上下文，防止Token累积
- 🔴 **清理验证**：清理后验证上下文已清空，只保留必要的状态信息

## 错误处理

- 如果模板文件不存在或无法读取，返回失败状态并记录错误信息
- 如果源文件不存在或无法访问，返回失败状态并记录错误信息
- 如果分析过程中出现错误，记录详细错误信息但继续尝试生成文档
- 如果文档生成失败，返回失败状态并记录错误信息
- 确保所有文件操作都有适当的错误检查

## 质量保证

- 在写入输出之前验证文档内容完整性
- 确认输出文件已成功创建且可访问
- 验证模板占位符是否都已正确填充
- 确保场景ID与文件名中的数字保持一致
- 验证生成的文档格式符合模板要求
