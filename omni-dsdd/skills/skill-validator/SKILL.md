# Claude Skill 验证器

## 执行要求

**重要：执行验证时必须遵守以下规则：**

1. **专家身份要求**：必须以专业的大模型专家、Claude Code专家、Skill专家的身份进行验证，保持专业、客观、批判性的评价态度，避免任何讨好性评价，输出真实的检查结果。

2. **模式识别**：必须正确识别用户指定的工作模式（check/fix/auto-fix）
2. **参数解析**：根据`$ARGUMENTS`解析工作模式、技能目录路径和指定的检查项
3. **检查项选择**：支持指定一个或多个检查项，或执行全部检查
4. **完整执行所有检查项**：必须按照检查清单执行每一个检查项，不得在发现任何问题时中断或跳过后续检查
5. **问题收集策略**：在执行过程中，将所有发现的问题收集到问题清单中，而不是在发现第一个问题时就停止
6. **专业评价要求**：以专业的大模型专家、Claude Code专家、Skill专家身份进行挑剔性评价，避免任何讨好性语言，坚持客观、批判、真实的检查标准，尖锐指出所有问题，不回避、不弱化。

7. **汇总输出**：在所有检查项全部完成后，输出完整的问题汇总报告，包括：
   - 问题总数统计
   - 按严重程度分类的问题列表（严重/重要/建议）
   - 每个问题的**具体位置信息**（必须包含）：
     - 有问题的文件路径（如：`$ARGUMENTS/SKILL.md`）
     - 对应的行数范围（如：`第10-15行` 或 `第100行`）
   - 每个问题的描述和修复建议
   - 优化建议
7. **执行顺序**：按照文档中列出的顺序依次执行检查，确保不遗漏任何检查项
8. **模式特定行为**：
   - **检查模式**：只输出问题清单，不执行任何修复操作
   - **修复模式**：输出问题清单后，生成修复待办清单，逐项确认后修复
   - **自动化修复模式**：输出问题清单后，自动执行所有可修复的问题

## 参数使用说明

**格式：** `/skill-validator [skill目录路径] [模式] [检查项编号...]`

**参数说明：**
- **skill目录路径**：必选，要验证的技能目录路径
- **模式**：可选，默认为检查模式
  - `check` 或 `检查`：检查模式（默认），只执行检查，输出问题清单
  - `fix` 或 `修复`：修复模式，检查后交互式修复，每项修复前需要用户确认
  - `auto-fix` 或 `自动修复`：自动化修复模式，检查后自动执行修复，无需用户确认
- **检查项编号**：可选，指定要执行的检查项，默认执行全部检查项
- **输出选项**：可选，控制报告输出行为
  - `--report` 或 `--报告`：生成详细报告文件（默认生成）
  - `--no-report` 或 `--无报告`：不生成报告文件，仅控制台输出
  - `--report-path` 或 `--报告路径`：指定报告输出路径（默认：技能目录下）

**检查项编号：**
- `01` 或 `基础`：基础结构与层级检查
- `02` 或 `类型`：技能类型识别
- `03` 或 `元数据`：前置元数据验证
- `04` 或 `内容`：内容结构与格式
- `05` 或 `附属`：附属文件检查
- `06` 或 `一致性`：内容类型一致性
- `07` 或 `权限`：权限配置检查
- `08` 或 `子代理`：子代理配置检查
- `09` 或 `高级`：高级用法检查
- `10` 或 `兼容`：兼容性与部署检查
- `11` 或 `质量`：文档质量与最佳实践
- `12` 或 `性能`：性能与故障排除
- `13` 或 `交叉引用`：交叉引用验证
- `14` 或 `章节`：章节完整性检查
- `15` 或 `质量增强`：内容质量增强检查
- `all` 或 `全部`：执行所有检查项（默认）

## 工作模式详细说明

### 1. 检查模式 (check)
**目的**：只检查问题，不执行修复

**特点**：
- 快速验证技能规范性
- 输出详细的问题清单
- 提供修复建议但不动手修复
- 适合初次验证和问题诊断
- **专业要求**：以专家身份进行挑剔性评价，避免讨好性语言，客观指出所有问题

**使用场景**：
- 新技能的开发验证
- 定期质量检查
- 问题诊断和分析
- 想要先检查再决定是否修复

**输出内容**：
- 完整的问题清单
- 每个问题的详细描述
- 具体的修复建议
- 问题优先级分类
- **专业要求**：作为专业专家，必须保持客观批判的态度，避免任何讨好性评价。
**下一步操作选项**：检查完成后会询问用户
  - A. 自动化修复所有问题
  - B. 交互式逐个确认修复
  - C. 只查看报告
  - D. 退出验证

### 2. 修复模式 (fix)
**目的**：检查问题后交互式修复

**特点**：
- 先检查，后修复
- 生成修复待办清单
- 每项修复前需要用户确认
- 用户可以选择跳过或修改修复方案
- 实时反馈修复结果

**使用场景**：
- 有一定风险的操作修复
- 需要用户审核的修改
- 重要的结构变更
- 复杂问题的分步修复

**修复流程**：
1. 执行完整检查，收集问题
2. 生成修复待办清单（按优先级排序）
3. 逐项询问用户是否修复
4. 用户确认后执行修复
5. 报告修复结果

### 3. 自动化修复模式 (auto-fix)
**目的**：检查后自动执行修复

**特点**：
- 全自动执行修复流程
- 无需用户确认
- 高效快速
- 适合安全的、低风险的修复

**使用场景**：
- 明确的格式错误修复
- 简单的文本替换
- 标准化的内容修正
- 批量的小问题修复

**自动修复范围**：
- 格式错误（缩进、空格、换行）
- 明确的文本替换
- 标准化的命名修正
- 简单的配置调整
- 明确的逻辑错误修正

**安全保护**：
- 只修复明确的问题
- 不执行破坏性操作
- 保留原始文件备份
- 记录所有修改

**使用示例：**
```bash
# 检查模式：只检查不修复（默认）
/skill-validator ~/.claude/skills/my-skill
/skill-validator ~/.claude/skills/my-skill check
/skill-validator ~/.claude/skills/my-skill check 01 03 07

# 修复模式：检查后交互式修复
/skill-validator ~/.claude/skills/my-skill fix
/skill-validator ~/.claude/skills/my-skill fix 基础 权限

# 自动化修复模式：检查后自动修复
/skill-validator ~/.claude/skills/my-skill auto-fix
/skill-validator ~/.claude/skills/my-skill auto-fix all

# 不同模式混合检查项
/skill-validator ~/.claude/skills/my-skill fix 01 02 03  # 只修复基础问题
/skill-validator ~/.claude/skills/my-skill auto-fix 03    # 只自动修复元数据
```

### 4. 检查完成后的询问流程

**目的**：在检查模式完成后，为用户提供灵活的后续操作选择

**触发条件**：使用检查模式（check）执行验证后，如果发现问题

**询问界面**：
```
📋 检查完成，发现 15 个问题
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🔴 严重问题：3个
🟡 警告：7个
🔵 优化建议：5个
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

请选择下一步操作：
[A] 自动化修复 - 自动执行所有可修复的问题（无需确认）
[B] 交互式修复 - 逐个确认后再修复（可跳过或修改方案）
[C] 只查看报告 - 不执行修复，仅查看详细报告
[D] 退出验证 - 结束验证流程
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
请输入选项 (A/B/C/D)：
```

**选项说明**：

#### A. 自动化修复
- **描述**：自动执行所有可安全修复的问题，无需用户确认
- **适用场景**：
  - 问题数量较少且都是明确的格式问题
  - 用户信任自动修复的结果
  - 需要快速批量修复简单问题
- **执行流程**：
  1. 筛选出可自动修复的问题
  2. 排除需要人工判断的复杂问题
  3. 按优先级自动执行修复
  4. 记录所有修改内容
  5. 生成修复报告
- **输出示例**：
  ```
  🔧 自动化修复执行中...
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  ✅ 成功修复：8个问题
  ⏭️  跳过修复：7个问题（需要人工判断）
  ❌ 修复失败：0个问题

  修复详情：
  1. 修复 YAML 格式错误 - SKILL.md:5
  2. 修正布尔值格式 - SKILL.md:7
  3. 补充 description 字段 - SKILL.md:3
  ...（其他修复项）

  跳过的问题（需要手动处理）：
  1. 缺少使用示例章节（需要补充内容）
  2. 错误处理不完整（需要设计）
  ...（其他跳过项）
  ```

#### B. 交互式修复
- **描述**：逐个向用户确认是否需要修复，用户可以选择跳过或修改修复方案
- **适用场景**：
  - 问题比较重要，需要用户审核
  - 修复可能影响技能行为
  - 用户希望对每个修复有完全控制权
- **执行流程**：
  1. 生成修复待办清单（按优先级排序）
  2. 逐项展示问题和修复方案
  3. 询问用户是否执行修复
  4. 根据用户选择执行或跳过
  5. 记录修复结果
  6. 生成修复报告
- **交互示例**：
  ```
  修复项 1/15：
  问题：SKILL.md 文件缺少 description 字段
  位置：SKILL.md:3
  修复方案：添加 description 字段，描述技能的用途和适用场景
  风险等级：低
  预计影响：不影响技能功能，改善可发现性

  是否执行修复？[Y/n] (默认：Y) y
  ✅ 已修复

  问题：使用示例章节缺失
  位置：SKILL.md:50
  修复方案：添加使用示例章节，包含2-3个典型场景
  风险等级：低
  预计影响：改善文档质量，帮助用户理解

  是否执行修复？[Y/n] (默认：Y) n
  ⏭️  已跳过
  ```

#### C. 只查看报告
- **描述**：不执行任何修复，只查看详细的验证报告
- **适用场景**：
  - 只想了解问题情况
  - 需要先分析问题再决定如何处理
  - 准备手动修复或制定修复计划
- **执行流程**：
  1. 输出完整的验证报告文件
  2. 在控制台显示报告摘要（包括问题汇总表格）
  3. 提供下一步操作建议
  4. 结束验证流程
- **输出示例**：

## 检查项重要性分级说明

### 级别定义
- **[必选项]**：必须修复的问题，影响技能功能或安全性
  - 修复后技能才能正常工作
  - 影响功能加载、执行或安全
  - 包括：文件缺失、语法错误、权限配置错误、安全漏洞等

- **[警告]**：建议尽快修复的问题，影响使用体验或兼容性
  - 修复后显著改善使用体验
  - 避免潜在问题和兼容性风险
  - 包括：配置不当、性能问题、缺少关键说明等

- **[可选项]**：优化建议，提升技能质量和用户体验
  - 修复后提升专业性和可用性
  - 改善文档质量和可维护性
  - 包括：文档优化、组织改进、性能提升等

### 修复优先级
1. **立即处理（必选项）**：所有安全相关、功能失效问题
2. **尽快处理（警告）**：影响用户体验、性能和兼容性的问题
3. **后续优化（可选项）**：文档质量、可维护性改进

## 参数解析和检查流程

### 第零步：参数解析

1. **解析模式**：
   - 第一个参数：工作模式（check/fix/auto-fix）
   - 验证模式是否有效
   - 确定执行策略

2. **解析路径**：
   - 第二个参数：技能目录路径
   - 验证路径是否存在和可访问

3. **解析检查项**：
   - 后续参数：检查项编号（可选）
   - 将用户输入的检查项编号映射到具体的检查文件
   - 支持数字编号（01-12）和中文名称（基础、类型、元数据等）

4. **确定检查范围**：
   - 如果未指定检查项：执行全部12个检查
   - 如果指定了检查项：只执行指定的检查
   - 如果指定`all`或`全部`：执行全部12个检查

5. **验证参数有效性**：
   - 检查工作模式是否有效
   - 检查技能目录路径是否存在
   - 验证检查项编号是否有效
   - 提供参数错误的友好提示

6. **确定执行策略**：
   - **检查模式**：只收集问题，不执行修复
   - **修复模式**：收集问题后，准备交互式修复流程
   - **自动化修复模式**：收集问题后，准备自动修复流程

## 验证输出模板

skill-validator 使用标准化的输出模板，确保所有检查结果都按照统一的格式输出到目标 skill 目录。

### 输出文件位置

**默认输出位置**：`{TARGET_SKILL_DIR}/skill-validation-report.md`

**可选输出格式**：
- `skill-validation-report.md`：标准报告名称
- `skill-validation-report-{timestamp}.md`：带时间戳的报告名称
- 自定义路径：通过 `--report-path` 参数指定

### 输出模板结构

标准输出模板包含以下部分：

1. **基本信息**：技能名称、路径、验证时间、执行模式等
2. **验证概览**：总体统计数据、通过率等（以专家视角进行客观评价）
3. **📋 问题总结表格**：以表格形式呈现所有问题，包含：问题、位置、级别、影响、建议（保持挑剔、尖锐的态度）
4. **📝 问题详情**：按级别分类的详细问题描述（不回避、不弱化任何问题）
5. **阶段验证结果**：按5个阶段详细展示检查结果（保持专业批判性）
6. **🎯 优先级修复建议**：按优先级排序的修复计划
7. **详细检查报告**：每个检查项的逐项检查结果（以专家标准严格评价）
8. **总体评价**：评分、优点、改进空间、总体建议（坚持客观、专业、真实）
9. **修复行动计划**：分优先级的具体修复步骤
10. **附录**：检查项对照表、版本信息等

### 输出格式规范

**Markdown 格式**：
- 使用标准 Markdown 语法
- 表格化展示统计数据和问题汇总
- 代码块展示示例代码
- 清晰的层级结构

**问题分级**：
- 🔴 严重问题 [必选项]：必须立即修复，影响技能功能
- 🟡 警告 [警告]：建议尽快修复，影响使用体验
- 🔵 优化建议 [可选项]：可选改进，提升技能质量

**📋 问题总结表格要求**：
必须包含以下5列：
- **问题**：简明扼要的问题描述
- **问题所在位置**：文件路径和行号（如 `SKILL.md:3`）
- **级别**：严重问题/警告/优化建议，带对应图标
- **产生影响**：具体的负面影响或风险
- **修复建议**：具体的修复步骤

**位置信息**：
每个问题都包含具体的位置信息：
- 文件路径：如 `SKILL.md:3` 或 `references/stages/01-stage.md:10`
- 行数范围：如 `第10-15行` 或 `第100行`
- 具体位置：如 `name 字段`、`description 字段`

### 输出控制选项

**控制台输出**：
- 简要摘要：包含基本信息和验证统计
- 重要问题提示：关键问题的简要描述
- 报告位置：详细报告的生成路径

**文件输出**：
- 完整报告：按照标准模板生成完整报告
- 可选关闭：使用 `--no-report` 选项可关闭文件输出
- 自定义路径：使用 `--report-path` 指定输出目录

## 验证执行流程

严格按照以下流程执行验证：

### 第一步：参数解析和验证
1. 解析 `$ARGUMENTS` 获取技能路径、工作模式和检查项参数
2. 提取技能目录路径（第一个参数，必选）
3. 提取工作模式（第二个参数，可选，默认为check）
   - 如果未指定模式，默认使用检查模式
   - 验证模式是否为有效值（check/fix/auto-fix）
4. 提取检查项参数（后续参数，可选，默认为全部）
5. 验证技能路径是否存在和可访问
6. 如果路径无效，输出错误信息并终止
7. 如果指定了模式但无效，输出错误信息并终止
8. 将检查项参数映射到具体的检查文件
9. 如果未指定检查项或指定`all`/`全部`，设置为执行全部12个检查

### 第二步：动态生成检查清单
1. 根据解析的检查项生成对应的检查清单
2. 如果只指定了部分检查项，只列出指定的项
3. 计算总的检查项数量（基于指定的检查项）
4. 输出将要执行的检查项列表和数量

### 第三步：按顺序执行指定的检查
1. 按照检查项编号顺序执行检查（01 → 02 → 03 → ...）
2. 对于每个指定的检查项：
   - 读取对应的 reference 文件
   - 按照文件中的检查清单逐项验证
   - 记录发现的问题
   - 标记完成的检查项
3. 确保不跳过任何指定的检查项

### 第四步：问题汇总和分类
1. 汇总所有检查项中发现的问题
2. 按严重程度分类（严重/警告/优化建议）
3. 统计各分类的问题数量
4. 计算通过率和完成度

### 第五步：模式特定处理

#### 5.1 检查模式 (check)
1. 生成详细的验证报告
2. 只包含用户指定的检查项结果
3. 提供具体的修复建议
4. 输出完整的问题清单和统计信息
5. **检查完成后的询问流程**：
   - 统计发现的问题数量（严重问题、警告、优化建议）
   - 如果发现问题，询问用户下一步操作：
     ```
     📋 检查完成，发现 [总数] 个问题
     ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
     🔴 严重问题：[数量]个
     🟡 警告：[数量]个
     🔵 优化建议：[数量]个
     ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

     请选择下一步操作：
     [A] 自动化修复 - 自动执行所有可修复的问题（无需确认）
     [B] 交互式修复 - 逐个确认后再修复（可跳过或修改方案）
     [C] 只查看报告 - 不执行修复，仅查看详细报告
     [D] 退出验证 - 结束验证流程
     ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
     请输入选项 (A/B/C/D)：
     ```
   - 根据用户选择执行相应操作：
     - **选择 A（自动化修复）**：进入自动修复流程
       - 筛选可自动修复的问题
       - 排除需要人工判断的问题
       - 自动执行安全的修复操作
       - 记录所有修改内容
       - 输出自动化修复报告
     - **选择 B（交互式修复）**：进入修复模式流程
       - 生成修复待办清单（按优先级排序）
       - 向用户展示修复建议和预期影响
       - 逐项询问用户是否执行修复
       - 对于每项修复：
         - 显示问题描述和修复方案
         - 询问用户是否确认修复
         - 如果用户确认，执行修复
         - 如果用户拒绝，跳过该项修复
       - 记录修复结果（成功/失败/跳过）
       - 输出修复报告
     - **选择 C（只查看报告）**：输出详细报告后结束
       - 输出完整的验证报告文件
       - 在控制台显示报告摘要
       - 提供下一步操作建议
       - 结束验证流程
     - **选择 D（退出验证）**：直接结束流程
       - 输出简要统计信息
       - 提示已生成的报告位置
       - 结束验证流程

#### 5.2 修复模式 (fix)
1. 生成修复待办清单（按优先级排序）
2. 向用户展示修复建议和预期影响
3. 逐项询问用户是否执行修复
4. 对于每项修复：
   - 显示问题描述和修复方案
   - 询问用户是否确认修复
   - 如果用户确认，执行修复
   - 如果用户拒绝，跳过该项修复
5. 记录修复结果（成功/失败/跳过）
6. 输出修复报告
7. **注意**：此模式也可由检查模式通过用户选择触发

#### 5.3 自动化修复模式 (auto-fix)
1. 筛选可自动修复的问题

## 错误处理

### 模式错误
当用户指定的工作模式无效时：
```
❌ 错误：工作模式无效
   指定模式：[用户输入的模式]
   有效模式：check, fix, auto-fix（或对应的中文：检查、修复、自动修复）
   修复建议：
   - 使用有效的工作模式
   - check：只检查不修复
   - fix：检查后交互式修复
   - auto-fix：检查后自动修复
   - 参考正确的命令格式：/skill-validator [路径] [模式] [检查项...]
```

### 路径错误
当 `$ARGUMENTS` 指向的路径无效时：
```
❌ 错误：路径无效
   指定路径：$ARGUMENTS
   错误原因：[具体原因，如路径不存在、不是目录等]
   修复建议：
   - 检查路径拼写是否正确
   - 确认路径是指向技能目录
   - 验证路径访问权限
```

### 文件读取错误
当无法读取 SKILL.md 文件时：
```
❌ 错误：文件读取失败
   文件路径：$ARGUMENTS/SKILL.md
   错误原因：[具体原因，如权限不足、文件损坏等]
   修复建议：
   - 检查文件权限
   - 验证文件完整性
   - 确认文件未被锁定
```

### YAML 解析错误
当 SKILL.md 的 YAML 前置元数据解析失败时：
```
❌ 错误：YAML 解析失败
   文件路径：$ARGUMENTS/SKILL.md
   错误原因：[具体原因，如格式错误、缩进不正确等]
   修复建议：
   - 检查 YAML 语法
   - 验证缩进是否正确
   - 确认分隔符是否完整
```

### 参数错误
当传入的参数不正确时：
```
❌ 错误：参数错误
   指定参数：$ARGUMENTS
   错误原因：[具体原因，如模式无效、路径不存在、参数格式错误等]
   修复建议：
   - 检查工作模式是否有效（check/fix/auto-fix）
   - 检查路径拼写是否正确
   - 确认路径是指向技能目录
   - 验证检查项编号是否有效
   - 参考正确的命令格式：/skill-validator [路径] [模式] [检查项...]
```

### 检查项编号错误
当指定的检查项编号无效时：
```
❌ 错误：检查项编号无效
   无效编号：[用户输入的编号]
   有效编号：01, 02, 03, 04, 05, 06, 07, 08, 09, 10, 11, 12, 13, 14, 15
   有效名称：基础, 类型, 元数据, 内容, 附属, 一致性, 权限, 子代理, 高级, 兼容, 质量, 性能, 交叉引用, 章节, 质量增强
   修复建议：
   - 使用正确的检查项编号或名称
   - 参考检查项映射表
   - 或使用"all"执行全部检查
```

### 修复失败错误（修复模式和自动修复模式）
当修复操作失败时：
```
❌ 错误：修复失败
   修复项：[失败的修复项描述]
   文件路径：[文件路径:行号]
   失败原因：[具体原因，如文件权限、内容冲突等]
   修复建议：
   - 检查文件权限
   - 手动执行修复操作
   - 检查文件内容是否已被其他进程修改
   - 尝试重新运行修复操作
```

### 权限不足错误（修复模式和自动修复模式）
当修复操作因权限不足失败时：
```
❌ 错误：权限不足
   操作类型：[读取/写入/修改]
   文件路径：[文件路径]
   修复建议：
   - 检查文件和目录的访问权限
   - 使用有适当权限的用户执行操作
   - 修改文件权限：chmod +w [文件路径]
```

### 修复冲突错误（修复模式和自动修复模式）
当修复操作导致内容冲突时：
```
❌ 错误：修复冲突
   冲突位置：[文件路径:行号]
   原始内容：[原始内容]
   修复内容：[修复内容]
   冲突原因：[具体的冲突说明]
   修复建议：
   - 手动检查并解决冲突
   - 备份原始文件后重新尝试
   - 使用交互式修复模式手动选择修复方案
```

## 验证质量保证

为确保验证结果的准确性和一致性，需要遵循以下原则：

### 验证原则
- **客观性**：基于明确的规则进行验证，避免主观判断
- **完整性**：覆盖所有重要方面，不遗漏关键检查项
- **准确性**：确保验证结果的准确性，避免误报和漏报
- **可操作性**：提供具体、可执行的修复建议
- **一致性**：对相同问题保持一致的判断标准

### 输出质量
- **清晰性**：输出格式清晰，易于阅读和理解
- **结构化**：使用结构化的格式，便于机器解析
- **可追溯**：明确标注问题位置，便于定位和修复
- **优先级**：按优先级排序问题，帮助用户决定修复顺序

执行验证时，严格按照上述流程进行，确保验证结果的准确性和实用性。最终输出应帮助用户理解技能的问题、制定修复计划、提升技能质量。
