# 1. 兼容性与部署检查

兼容性检查确保技能与Claude Code生态系统的兼容性，避免使用不支持的特性。

## 1.1 版本兼容性

### 1.1.1 废弃功能避免
- [ ] **不使用已废弃的功能或字段** [必选项]：避免使用已废弃的特性
  - 验证方法：对照官方文档检查
  - 常见废弃内容：
    - 已废弃的字段
    - 已废弃的变量
    - 已废弃的语法

### 1.1.2 模型名称兼容
- [ ] **使用当前支持的模型名称** [警告]：使用有效的模型名称
  - 验证方法：检查 model 字段的值
  - 支持的模型：`sonnet`、`opus`、`haiku`
  - 错误示例：`claude-3`、`gpt4`
  - 正确示例：`sonnet`、`opus`

### 1.1.3 变量语法兼容
- [ ] **变量语法使用最新格式** [必选项]：使用当前的变量语法
  - 验证方法：检查变量语法
  - 当前支持的变量：
    - `$ARGUMENTS`
    - `$ARGUMENTS[N]`
    - `$N`
    - `${CLAUDE_SESSION_ID}`
    - `${CLAUDE_SKILL_DIR}`

## 1.2 插件兼容性

### 1.2.1 插件技能命名
- [ ] **插件技能使用命名空间** [可选项]：插件技能应使用 `plugin-name:skill-name` 格式
  - 验证方法：检查插件技能的命名
  - 错误示例：插件技能使用普通名称
  - 正确示例：`my-plugin:deploy-skill`

### 1.2.2 企业技能冲突避免
- [ ] **不使用与企业技能冲突的命名** [必选项]：避免命名冲突
  - 验证方法：检查是否与企业技能重名
  - 冲突处理：
    - 更改技能名称
    - 使用命名空间
    - 明确技能层级

## 1.3 钩子配置

### 1.3.1 hooks 配置语法
- [ ] **hooks 配置语法正确** [必选项]：确保钩子配置格式正确
  - 验证方法：检查 YAML 语法
  - 常用钩子类型：
    - `pre`：前置钩子
    - `post`：后置钩子
    - `error`：错误钩子

### 1.3.2 钩子类型有效性
- [ ] **钩子类型有效** [必选项]：使用支持的钩子类型
  - 验证方法：对照支持的钩子类型检查
  - 错误示例：使用不支持的钩子类型
  - 正确示例：使用 `pre`、`post`、`error` 等支持的钩子
