# 1. 技能类型识别

识别技能是参考类还是任务类，确保配置与内容类型匹配。

## 1.1 技能类型判断

- [ ] **识别技能类型** [警告]：根据技能内容和配置判断技能类型
  - 验证方法：分析技能的description、内容和配置
  - 类型定义：
    - **参考类技能**：提供知识、规范、说明，补充Claude工作背景
    - **任务类技能**：提供操作流程、执行步骤，完成特定任务
  - 判断依据：
    - 主要目的是提供知识还是执行操作
    - 内容格式是说明性还是步骤性
    - 是否需要用户手动调用

- [ ] **技能类型配置正确** [必选项]：技能类型与配置匹配
  - 验证方法：比较技能类型与YAML配置
  - 配置检查：
    - 参考类技能通常不禁止自动调用
    - 任务类技能通常建议禁止自动调用
  - 错误示例：配置与类型不匹配
  - 正确示例：配置反映实际技能类型

## 1.2 参考类技能检查

- [ ] **参考类技能特征识别** [必选项]：识别参考类技能的特征
  - 验证方法：检查技能是否符合参考类特征
  - 参考类特征：
    - 补充 Claude 工作所需的背景知识
    - 如代码规范、设计模式、风格指南、业务领域知识
    - 这类内容以内联方式加载，持续融入对话上下文
  - 典型示例：项目API规范、代码风格指南、业务规则说明
  - 错误示例：将任务类技能误判为参考类
  - 正确示例：
    ```yaml
    ---
    name: api-conventions
    description: 本项目 API 设计规范
    ---
    ```

- [ ] **参考类技能配置合理** [警告]：参考类技能配置建议
  - 验证方法：检查参考类技能的配置
  - 推荐配置：
    - 通常不设置 `disable-model-invocation: true`
    - description 强调知识补充和规范说明
    - 内容为知识性说明，不包含操作步骤
    - **如果被其他技能调用，必须设置为 `false` 或省略**
  - 不推荐的配置：
    ```yaml
    ---
    disable-model-invocation: true  # 参考类通常不需要禁止自动调用（除非被其他技能调用）
    ---
    ```

- [ ] **参考类内容特征正确** [必选项]：参考类内容应为知识性说明
  - 验证方法：检查内容类型
  - 内容特征：
    - 提供背景知识
    - 说明规范和标准
    - 解释设计模式
    - 描述业务规则
  - 错误示例：包含操作步骤、流程说明
  - 正确示例：
    ```markdown
    编写 API 接口时：
    - 遵循 RESTful 命名规范
    - 统一错误返回格式
    - 开启请求参数校验
    ```

## 1.3 任务类技能检查

- [ ] **任务类技能特征识别** [必选项]：识别任务类技能的特征
  - 验证方法：检查技能是否符合任务类特征
  - 任务类特征：
    - 为特定操作提供分步流程
    - 如部署、提交代码、代码生成
    - 这类操作通常需要手动通过 /技能名 调用
  - 典型示例：部署应用、运行测试、代码生成、数据处理
  - 错误示例：将参考类技能误判为任务类
  - 正确示例：
    ```yaml
    ---
    name: deploy
    description: 将应用部署至生产环境
    context: fork
    disable-model-invocation: true
    ---
    ```

- [ ] **任务类技能配置合理**：任务类技能配置建议
  - 验证方法：检查任务类技能的配置
  - 推荐配置：
    - 建议设置 `disable-model-invocation: true`
    - description 强调操作流程和执行步骤
    - 内容为操作性说明，包含明确的步骤
    - 必要时使用 `context: fork` 和 `agent`
    - **例外：如果被其他技能调用，应设置为 `false`**
  - 错误示例：任务类技能允许自动调用（除非被其他技能调用）
  - 正确示例：
    ```yaml
    ---
    name: deploy
    description: 将应用部署至生产环境
    context: fork
    disable-model-invocation: true  # 任务类建议禁止自动调用（不被其他技能调用时）
    ---
    ```
  - 调用例外：
    ```yaml
    ---
    name: base-deploy-helper
    description: 部署基础能力，被上层部署技能调用
    # 虽然涉及部署操作，但被其他技能调用，不能禁止自动调用
    ---
    ```

- [ ] **任务类内容特征正确** [必选项]：任务类内容应为操作性说明
  - 验证方法：检查内容类型
  - 内容特征：
    - 提供明确的步骤
    - 有具体的操作流程
    - 有预期的输出
    - 有验证方法
  - 错误示例：无明确步骤，纯知识性说明
  - 正确示例：
    ```markdown
    部署应用流程：
    1. 运行完整测试套件
    2. 编译构建应用
    3. 推送至部署目标
    4. 验证部署结果
    ```

## 1.4 类型一致性验证

- [ ] **配置与内容类型一致** [必选项]：确保配置反映内容类型
  - 验证方法：比较配置和内容
  - 一致性检查：
    - 参考类 → 内容为知识性说明
    - 任务类 → 内容为操作性说明
  - 错误示例：
    - 配置显示为任务类，但内容为参考类
    - 配置显示为参考类，但内容为任务类
  - 正确示例：配置和内容类型完全一致

- [ ] **调用方式与内容匹配** [必选项]：调用方式应适合内容类型
  - 验证方法：检查调用权限配置
  - 匹配规则：
    - 参考类：适合自动调用，补充知识
    - 任务类：适合手动调用，执行操作
  - 错误示例：
    - 任务类技能允许自动调用
    - 参考类技能禁止自动调用
  - 正确示例：调用方式与内容类型完全匹配
