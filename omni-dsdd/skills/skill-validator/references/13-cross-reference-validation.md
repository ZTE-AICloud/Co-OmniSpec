# 1. 交叉引用验证

交叉引用验证确保技能文档中所有引用的文件和链接都能正确解析，避免无效引用和循环依赖。

## 1.1 文件引用有效性检查

### 1.1.1 相对链接验证
- [ ] **所有相对链接能解析到现有文件** [必选项]：确保 Markdown 链接指向的文件存在
  - 验证方法：从 Markdown 链接中提取相对路径，验证文件相对于 SKILL.md 是否存在
  - 检查类型：
    - Markdown 链接格式：`[链接文本](相对路径)`
    - 文件引用：`references/stages/01-stage.md`
    - 目录引用：`examples/`
  - 错误示例：引用不存在的文件或路径
  - 正确示例：所有引用的文件都实际存在于技能目录中
  - 自动修复：否

### 1.1.2 阶段文档引用验证
- [ ] **阶段描述中引用的阶段文档必须存在** [必选项]：确保阶段文档在 references/stages/ 中
  - 验证方法：从阶段章节中提取阶段文件引用，并在 references/stages/ 目录中验证
  - 检查内容：
    - 阶段文档路径格式正确
    - 文件实际存在于 references/stages/ 目录
    - 文件命名符合 NN-description.md 格式
  - 错误示例：引用不存在的阶段文档或路径错误
  - 正确示例：所有引用的阶段文档都存在且路径正确
  - 自动修复：否

### 1.1.3 references/ 目录存在性检查
- [ ] **当阶段引用阶段文档时，references/ 目录应存在** [必选项]
  - 验证方法：如果任何阶段引用了阶段文档，验证 references/ 目录是否存在
  - 检查条件：
    - SKILL.md 中有阶段文档的引用
    - 引用路径包含 references/ 或 stages/
  - 错误示例：引用阶段文档但 references/ 目录不存在
  - 正确示例：references/ 目录存在并包含被引用的文件
  - 自动修复：否

### 1.1.4 核心规则文件引用验证
- [ ] **如果 SKILL.md 引用了 core-rules.md，它必须存在** [必选项]
  - 验证方法：扫描 references/core-rules.md 的引用并验证文件存在
  - 检查内容：
    - 文件路径：references/core-rules.md
    - 文件存在性
    - 文件内容有效性
  - 错误示例：引用 core-rules.md 但文件不存在
  - 正确示例：core-rules.md 存在且可访问
  - 自动修复：否

### 1.1.5 数据文件引用验证
- [ ] **如果 SKILL.md 引用了 data.md，它必须存在** [必选项]
  - 验证方法：扫描 references/data.md 的引用并验证文件存在
  - 检查内容：
    - 文件路径：references/data.md
    - 文件存在性
    - 数据格式正确性
  - 错误示例：引用 data.md 但文件不存在
  - 正确示例：data.md 存在且数据格式正确
  - 自动修复：否

### 1.1.6 Token 管理文件验证
- [ ] **复杂多阶段 skill 应有 references/token-management.md** [必选项]
  - 验证方法：对于 4+ 阶段的 skill，检查 references/token-management.md 是否存在
  - 检查条件：
    - skill 包含 4 个或更多阶段
    - 没有引用 token-management.md
  - 错误示例：复杂多阶段 skill 缺少 token 管理指导
  - 正确示例：存在 token-management.md 文件，包含：
    - Token 预算分配
    - 上下文清理策略
    - 阶段间数据传递优化
  - 自动修复：否

## 1.2 文件命名规范检查

### 1.2.1 阶段文件命名约定
- [ ] **references/stages/ 中的阶段文件应遵循 NN-description.md 命名约定** [必选项]
  - 验证方法：列出 references/stages/ 中的文件，检查是否匹配模式 `^\d{2}-.*\.md$`
  - 命名规则：
    - 以两位数字开头（01, 02, 03...）
    - 使用连字符分隔数字和描述
    - 描述使用 kebab-case 命名
    - 扩展名为 .md
  - 错误示例：`stage1.md`、`01.md`、`first-stage.md`
  - 正确示例：`01-analysis.md`、`02-design.md`、`03-implementation.md`
  - 自动修复：否

### 1.2.2 文件名一致性检查
- [ ] **文件名在不同引用中保持一致** [必选项]
  - 验证方法：检查同一文件在不同位置的引用是否使用相同的名称
  - 检查内容：
    - 路径分隔符一致（统一使用 `/`）
    - 大小写一致（文件系统区分大小写时）
    - 不混用相对和绝对引用
  - 错误示例：
    - 一处引用：`references/stages/01-stage.md`
    - 另一处引用：`./references/stages/01-stage.md`
  - 正确示例：所有引用使用统一的路径格式
  - 自动修复：否

## 1.3 循环引用检查

### 1.3.1 文件循环引用检测
- [ ] **无损坏的 markdown 链接（链接文本存在但目标文件缺失）** [必选项]
  - 验证方法：提取所有 markdown 链接 `[text](path)` 并验证目标文件是否存在
  - 检查内容：
    - 链接语法正确性
    - 目标文件存在性
    - 路径有效性
  - 错误示例：链接到不存在的文件或无效的路径
  - 正确示例：所有链接都指向实际存在的文件
  - 自动修复：否

### 1.3.2 依赖关系循环检测
- [ ] **避免文件之间的循环引用** [必选项]
  - 验证方法：构建文件引用图并检查是否有环路
  - 检查内容：
    - A.md 引用 B.md，B.md 引用 A.md
    - 更复杂的循环引用链
  - 影响：
    - 可能导致无限递归加载
    - 影响性能
    - 消耗上下文配额
  - 错误示例：存在循环引用关系
  - 正确示例：引用关系为有向无环图（DAG）
  - 自动修复：否

### 1.3.3 技能间循环调用检测
- [ ] **避免技能间的循环调用** [必选项]
  - 验证方法：分析技能调用关系图
  - 检查内容：
    - 技能 A 调用技能 B
    - 技能 B 又调用技能 A
  - 错误示例：存在技能间循环调用
  - 正确示例：技能调用关系为有向无环图
  - 自动修复：否

## 1.4 引用完整性检查

### 1.4.1 未引用文件检测
- [ ] **如果 skill 目录包含支持文件，应在 SKILL.md 中引用它们** [必选项]
  - 验证方法：列出 skill 目录中的文件（排除 SKILL.md），检查是否有未被引用的支持文件
  - 支持文件类型：
    - scripts/ 目录中的脚本
    - examples/ 目录中的示例
    - references/ 目录中的文档
    - template.md 或 templates/ 中的模板
  - 错误示例：存在支持文件但 SKILL.md 中未引用
  - 正确示例：
    ```markdown
    ## 支持文件

    详细 API 文档见 [reference.md](reference.md)
    运行捆绑脚本：python ${CLAUDE_SKILL_DIR}/scripts/analyze.py
    使用示例参考 [examples/](examples/) 目录
    ```
  - 自动修复：否

### 1.4.2 孤立文件检测
- [ ] **避免技能目录中存在孤立的文件** [可选项]
  - 验证方法：检查是否有既未被引用也没有明确用途的文件
  - 检查条件：
    - 文件未被 SKILL.md 引用
    - 文件也不在其他附属文件中被引用
    - 文件不是标准的附属文件类型
  - 错误示例：存在孤立文件，影响技能的清晰度
  - 正确示例：所有文件都有明确的用途和引用
  - 自动修复：否

### 1.4.3 引用有效性验证
- [ ] **所有引用的链接和路径都是有效的** [必选项]
  - 验证方法：逐个验证所有引用的文件和目录
  - 验证内容：
    - 文件存在性
    - 路径格式正确性
    - 访问权限
  - 错误示例：引用的文件不存在或路径无效
  - 正确示例：所有引用都是有效且可访问的
  - 自动修复：否

## 1.5 引用组织性检查

### 1.5.1 引用分组合理
- [ ] **引用应按类型或用途分组** [可选项]
  - 验证方法：检查引用的组织方式
  - 推荐分组方式：
    - 按文件类型（文档/示例/脚本）
    - 按功能分组（API/配置/部署）
    - 按复杂度分组（基础/进阶/高级）
  - 错误示例：引用混乱，无分组
  - 正确示例：
    ```markdown
    ## 补充资源

    ### 实现细节
    - 阶段文档：[references/stages/](references/stages/)
    - 核心规则：[references/core-rules.md](references/core-rules.md)

    ### 使用示例
    - 基础示例：[examples/basic.md](examples/basic.md)
    - 高级示例：[examples/advanced.md](examples/advanced.md)

    ### 辅助脚本
    - 设置脚本：[scripts/setup.sh](scripts/setup.sh)
    ```
  - 自动修复：否

### 1.5.2 引用说明清晰
- [ ] **每个引用都应有用途说明** [必选项]
  - 验证方法：检查引用是否附带说明文字
  - 说明内容：
    - 文件内容概述
    - 使用场景说明
    - 重要注意事项
  - 错误示例：孤立的引用，无任何说明
  - 正确示例：
    ```markdown
    完整 API 文档：[references/stages/01-stage1.md](references/stages/01-stage1.md)
    - 包含所有 API 接口的详细说明
    - 提供请求/响应示例
    - 说明错误码和处理方式
    ```
  - 自动修复：否

### 1.5.3 引用层次清晰
- [ ] **建立合理的引用层次结构** [可选项]
  - 验证方法：检查引用的层次性
  - 推荐层次：
    - 主文件（SKILL.md）→ 一级引用
    - 一级引用文件 → 二级引用
    - 避免复杂的交叉引用网络
  - 错误示例：复杂的交叉引用网络，难以理解
  - 正确示例：清晰的层次化引用结构
  - 自动修复：否
