# 1. 内容结构检查

正文内容是技能的核心执行逻辑，需要确保其结构清晰、逻辑合理、易于理解和执行。

## 1.1 内容完整性检查

### 1.1.1 分隔符检查
- [ ] **前置元数据与正文分隔明确** [必选项]：必须有 `---` 分隔符
  - 验证方法：检查 YAML 块前后是否有 `---` 分隔符
  - 错误示例：
    ```yaml
    ---
    name: my-skill
    description: 技能描述
    正文内容...  # 缺少结束分隔符
    ```
  - 正确示例：
    ```yaml
    ---
    name: my-skill
    description: 技能描述
    ---

    正文内容...
    ```

- [ ] **分隔符位置正确** [必选项]：分隔符应单独成行
  - 验证方法：检查 `---` 前后是否为空行或文件开头/结尾
  - 错误示例：
    ```yaml
    ---name: my-skill---  # 分隔符位置错误
    ```
  - 正确示例：
    ```yaml
    ---
    name: my-skill
    ---
    ```

### 1.1.2 内容一致性检查
- [ ] **正文内容与 description 一致** [必选项]：技能描述应准确反映实际内容
  - 验证方法：比较 description 与正文内容的功能描述
  - 错误示例：description 说"部署代码"但正文是"解释代码"
  - 正确示例：description 和正文内容完全对应

- [ ] **内容逻辑清晰** [必选项]：正文应有明确的目标和执行逻辑
  - 验证方法：检查内容是否有清晰的目标说明和逻辑流程
  - 错误示例：内容混乱，缺乏明确的目标和步骤
  - 正确示例：
    ```markdown
    # 部署应用流程

    1. 执行测试用例
    2. 打包构建项目
    3. 推送至部署服务器
    4. 验证部署结果
    ```

### 1.1.3 内容长度控制
- [ ] **内容长度合理** [可选项]：建议 SKILL.md 主文件在500行以内
  - 验证方法：统计文件行数
  - 错误示例：单文件超过1000行，难以维护
  - 正确示例：主文件简洁，复杂内容拆分到附属文件

- [ ] **复杂内容拆分** [警告]：超过500行的内容应拆分为附属文件
  - 验证方法：检查是否有复杂的实现逻辑或大量示例
  - 错误示例：将所有内容堆在 SKILL.md 中
  - 正确示例：
    ```
    my-skill/
    ├── SKILL.md          # 主文件（<500行）
    ├── references/        # 技能实现细节目录
    └── examples/
        ├── example1.md
        └── example2.md
    ```

## 1.2 内容类型一致性检查

### 1.2.1 参考类技能特征
- [ ] **参考类技能特征** [必选项]：内容侧重知识补充，无操作步骤
  - 验证方法：检查内容是否为知识性、说明性内容
  - 典型特征：
    - 提供背景知识
    - 说明设计模式
    - 解释业务规则
    - 描述代码规范

- [ ] **参考类技能无执行步骤** [必选项]：不应包含明确的执行步骤
  - 验证方法：检查是否有"1. 2. 3."这样的步骤编号
  - 错误示例：参考类技能中包含操作步骤
  - 正确示例：
    ```markdown
    # API 设计规范

    - 遵循 RESTful 命名规范
    - 统一错误返回格式
    - 开启请求参数校验
    ```

### 1.2.2 任务类技能特征
- [ ] **任务类技能特征** [必选项]：内容侧重操作流程，有明确步骤
  - 验证方法：检查内容是否为操作性、流程性内容
  - 典型特征：
    - 部署流程
    - 提交流程
    - 生成流程
    - 验证流程

- [ ] **任务类技能有明确步骤** [必选项]：应包含清晰的执行步骤
  - 验证方法：检查是否有步骤编号或明确的操作指引
  - 错误示例：任务类技能缺乏明确的执行步骤
  - 正确示例：
    ```markdown
    # 部署应用流程

    1. 运行完整测试套件
    2. 编译构建应用
    3. 推送至部署目标
    4. 验证部署结果
    ```

## 1.3 变量使用检查

### 1.3.1 $ARGUMENTS 变量
- [ ] **$ARGUMENTS 使用正确** [必选项]：完整参数字符串替换
  - 验证方法：检查 `$ARGUMENTS` 的使用场景
  - 用途：接收用户传入的所有参数
  - 错误示例：`$ARGUMENTS[0]`（语法错误）
  - 正确示例：
    ```markdown
    按照 $ARGUMENTS 的要求执行任务...
    ```

- [ ] **参数引用一致性** [必选项]：如果使用变量，应在正文中引用
  - 验证方法：检查是否使用了 $ARGUMENTS 或其他变量
  - 默认行为：如果正文未引用变量，参数会自动追加到内容末尾

### 1.3.2 $ARGUMENTS[N] 和 $N 变量
- [ ] **$ARGUMENTS[N] 语法正确** [必选项]：使用方括号索引
  - 验证方法：检查索引语法
  - 错误示例：`$ARGUMENTS(0)`、`$ARGUMENTS_0`
  - 正确示例：
    ```markdown
    将 $ARGUMENTS[0] 从 $ARGUMENTS[1] 迁移至 $ARGUMENTS[2]
    ```

- [ ] **$N 简写形式** [必选项]：支持 $0, $1, $2 等简写
  - 验证方法：检查简写语法的使用
  - 错误示例：`$[0]`、`$arg0`
  - 正确示例：
    ```markdown
    将 $0 从 $1 迁移至 $2
    ```

- [ ] **索引从0开始** [必选项]：确保使用正确的索引
  - 验证方法：检查索引是否从 0 开始
  - 错误示例：将第一个参数当作 $1
  - 正确示例：第一个参数是 $0

### 1.3.3 ${CLAUDE_SESSION_ID} 变量
- [ ] **${CLAUDE_SESSION_ID} 使用场景合理** [必选项]：会话ID的使用
  - 验证方法：检查是否用于日志、会话专属文件等场景
  - 典型用途：
    - 日志文件命名：`logs/${CLAUDE_SESSION_ID}.log`
    - 会话专属配置
    - 临时文件命名

- [ ] **变量语法正确** [必选项]：使用花括号包裹
  - 验证方法：检查变量语法
  - 错误示例：`$CLAUDE_SESSION_ID`（缺少花括号）
  - 正确示例：
    ```markdown
    将日志写入 logs/${CLAUDE_SESSION_ID}.log
    ```

### 1.3.4 ${CLAUDE_SKILL_DIR} 变量
- [ ] **${CLAUDE_SKILL_DIR} 引用正确** [必选项]：技能目录路径的引用
  - 验证方法：检查是否用于引用技能内部的附属文件
  - 典型用途：
    - 脚本路径引用：`${CLAUDE_SKILL_DIR}/scripts/helper.sh`
    - 模板路径引用：`${CLAUDE_SKILL_DIR}/templates/template.md`
    - 示例文件路径引用

- [ ] **路径构建正确** [必选项]：确保路径拼接正确
  - 验证方法：检查路径分隔符和路径结构
  - 错误示例：
    ```markdown
    ${CLAUDE_SKILL_DIR}scripts/helper.sh  # 缺少斜杠
    ```
  - 正确示例：
    ```markdown
    ${CLAUDE_SKILL_DIR}/scripts/helper.sh
    ```

- [ ] **插件技能路径正确** [必选项]：插件技能指向插件内技能目录
  - 验证方法：检查插件技能的路径指向
  - 错误示例：指向插件根目录而非技能目录
  - 正确示例：指向插件内具体的技能目录

### 1.3.5 变量语法通用检查
- [ ] **变量名拼写正确**：确保变量名准确无误
  - 验证方法：检查变量名拼写
  - 错误示例：`$ARGUMENT`、`$CLAUSE_SESSION_ID`
  - 正确示例：`$ARGUMENTS`、`${CLAUDE_SESSION_ID}`

- [ ] **无多余空格**：变量语法中不应有多余空格
  - 验证方法：检查变量表达式
  - 错误示例：`$ ARGUMENTS`、`${ CLAUDE_SESSION_ID }`
  - 正确示例：`$ARGUMENTS`、`${CLAUDE_SESSION_ID}`

- [ ] **括号匹配**：确保花括号成对出现
  - 验证方法：检查括号匹配
  - 错误示例：`${CLAUDE_SESSION_ID`、`CLAUDE_SESSION_ID}`
  - 正确示例：`${CLAUDE_SESSION_ID}`

## 1.4 内容格式组织检查

### 1.4.1 标题层级
- [ ] **使用清晰的标题层级**：使用合理的标题结构
  - 验证方法：检查标题的层级关系
  - 层级规则：
    - 使用 H1 (`#`) 作为主标题（通常只有一个）
    - 使用 H2 (`##`) 作为主要章节
    - 使用 H3 (`###`) 作为子章节
    - 避免跳级使用（如 H2 直接跳到 H4）

- [ ] **标题语义明确**：标题应清晰反映内容
  - 验证方法：检查标题的语义
  - 错误示例："第一部分"、"流程1"
  - 正确示例："部署流程"、"参数说明"、"使用示例"

### 1.4.2 步骤编号
- [ ] **步骤有明确的编号**：使用编号或列表表示步骤
  - 验证方法：检查步骤的表示方法
  - 支持的格式：
    ```markdown
    1. 第一步
    2. 第二步
    3. 第三步
    ```

    ```markdown
    - 第一步
    - 第二步
    - 第三步
    ```

- [ ] **步骤逻辑清晰**：步骤之间有明确的逻辑关系
  - 验证方法：检查步骤的顺序和关系
  - 错误示例：步骤混乱，无逻辑关系
  - 正确示例：步骤清晰，逻辑连贯

### 1.4.3 列表使用
- [ ] **使用要点列表提高可读性**：适当使用列表
  - 验证方法：检查列表的使用
  - 列表使用场景：
    - 列举多个选项
    - 列出检查项
    - 说明多个步骤
    - 列出注意事项

- [ ] **列表格式统一**：同一层级使用统一的列表符号
  - 验证方法：检查列表符号的一致性
  - 错误示例：
    ```markdown
    - 项目1
    * 项目2
    1. 项目3
    ```
  - 正确示例：
    ```markdown
    - 项目1
    - 项目2
    - 项目3
    ```

## 1.5 代码块和格式检查

### 1.5.1 代码块语法
- [ ] **代码块使用正确语法**：使用三个反引号包裹
  - 验证方法：检查代码块的 Markdown 语法
  - 错误示例：
    ```markdown
    ```
    代码内容  # 缺少结束标记
    ```
  - 正确示例：
    ```markdown
    ```bash
    echo "Hello World"
    ```
    ```

- [ ] **代码块指定语言**：为代码块指定语言类型以获得语法高亮
  - 验证方法：检查代码块开头是否指定语言
  - 常用语言：`bash`、`python`、`javascript`、`yaml`、`markdown`
  - 错误示例：不指定语言或使用不支持的语言
  - 正确示例：
    ```markdown
    ```python
    def hello():
        print("Hello World")
    ```
    ```

### 1.4.2 示例代码质量
- [ ] **示例代码可执行**：提供的示例代码应该是可运行的
  - 验证方法：检查示例代码的完整性
  - 错误示例：不完整的代码片段
  - 正确示例：完整、可执行的代码示例

- [ ] **示例代码有说明**：复杂示例应有详细注释
  - 验证方法：检查示例代码的注释
  - 错误示例：复杂代码无注释
  - 正确示例：
    ```python
    # 连接到数据库并执行查询
    def query_database(sql):
        conn = connect_to_database()  # 建立连接
        result = conn.execute(sql)     # 执行查询
        conn.close()                  # 关闭连接
        return result
    ```

### 1.4.3 文件引用格式
- [ ] **引用附属文件使用相对路径**：使用相对路径引用附属文件
  - 验证方法：检查文件引用的路径格式
  - 支持格式：
    - `references/stages/01-stage1.md`（子目录）
    - `./references/stages/01-stage1.md`（显式子目录）
    - `examples/example1.md`（子目录）

- [ ] **文件引用路径正确**：确保引用的文件存在
  - 验证方法：检查引用的文件是否实际存在
  - 错误示例：引用不存在的文件
  - 正确示例：引用实际存在的附属文件

- [ ] **无循环引用**：避免文件之间的循环引用
  - 验证方法：检查引用链是否有循环
  - 错误示例：A 引用 B，B 引用 A
  - 正确示例：单向引用或层次化引用

### 1.4.4 超链接格式
- [ ] **超链接格式正确**：使用标准的 Markdown 链接语法
  - 验证方法：检查链接语法
  - 错误示例：`[链接](path)`（被系统误解析）
  - 正确描述：使用标准的 Markdown 链接格式 `[文本](URL或路径)`

- [ ] **链接可访问性**：确保链接指向可访问的资源
  - 验证方法：检查链接的有效性
  - 错误示例：链接到不存在的资源或无效的 URL
  - 正确示例：链接到存在的附属文件或有效的 URL

### 1.4.5 Markdown 格式规范
- [ ] **标题层级合理**：使用正确的标题层级
  - 验证方法：检查标题的层级关系
  - 错误示例：从 H3 直接跳到 H5
  - 正确示例：H1 → H2 → H3 → H4 顺序使用

- [ ] **列表格式一致**：使用一致的列表格式
  - 验证方法：检查列表符号的使用
  - 错误示例：混用 `-`、`*`、`1.` 作为列表符号
  - 正确示例：同一层级使用统一的列表符号

- [ ] **空行使用合理**：适当使用空行提高可读性
  - 验证方法：检查空行的使用
  - 错误示例：过多或过少的空行
  - 正确示例：在段落、列表、代码块之间适当使用空行

### 1.4.6 字符串替换检查

- [ ] **字符串替换变量使用正确**：正确使用技能支持的字符串替换变量
  - 验证方法：检查技能内容中使用的替换变量是否在支持列表中
  - 支持的变量：
    - `$ARGUMENTS`：调用技能时传递的所有参数
    - `$ARGUMENTS[N]`：按0基索引访问特定参数（如 `$ARGUMENTS[0]`）
    - `$N`：`$ARGUMENTS[N]` 的简写，如 `$0`、`$1`
    - `$name`：在 `arguments` frontmatter 列表中声明的命名参数
    - `${CLAUDE_SESSION_ID}`：当前会话 ID
    - `${CLAUDE_EFFORT}`：当前工作量级别（low/medium/high/xhigh/max）
    - `${CLAUDE_SKILL_DIR}`：包含 skill 的 SKILL.md 文件的目录
  - 错误示例：使用不支持的变量如 `$USERNAME`、`${USER_HOME}`
  - 正确示例：
    ```yaml
    Log the following to logs/${CLAUDE_SESSION_ID}.log:
    $ARGUMENTS
    ```

- [ ] **$ARGUMENTS 使用规范**：正确使用所有参数占位符
  - 验证方法：检查 $ARGUMENTS 的使用方式
  - 使用规则：
    1. 如果内容中不存在 `$ARGUMENTS`，参数会自动追加到内容末尾
    2. 索引参数使用 `$ARGUMENTS[N]` 或 `$N` 访问特定参数
    3. `$ARGUMENTS` 占位符始终扩展为完整的参数字符串
  - 错误示例：混用 `$ARGUMENTS` 和索引参数导致混乱
  - 正确示例：
    ```yaml
    # 使用完整参数字符串
    Fix GitHub issue $ARGUMENTS following our coding standards.

    # 使用索引参数
    Migrate $0 component from $1 to $2. Preserve all existing behavior and tests.
    ```

- [ ] **索引参数使用正确**：正确使用 `$N` 或 `$ARGUMENTS[N]` 语法
  - 验证方法：检查索引参数的格式和范围
  - 语法规则：
    1. 使用 `$N` 简写，如 `$0` 表示第一个参数
    2. 使用 `$ARGUMENTS[N]` 完整形式
    3. 索引从 0 开始
    4. 多词参数需用引号包裹
  - 错误示例：`$1` 但只传递了一个参数
  - 正确示例：
    ```yaml
    # /migrate-component SearchBar React Vue
    Migrate $0 component from $1 to $2.
    # $0 = SearchBar, $1 = React, $2 = Vue
    ```

- [ ] **命名参数与 arguments 字段匹配**：命名参数必须在 arguments 列表中声明
  - 验证方法：检查 `$name` 占位符是否在 `arguments` frontmatter 中定义
  - 映射规则：名称按顺序映射到位置参数
  - 错误示例：
    ```yaml
    # 正文中使用 $issue 但未在 arguments 中声明
    Fix GitHub issue $issue.
    ```
  - 正确示例：
    ```yaml
    arguments: [issue, branch]
    # Fix GitHub issue $issue on branch $branch.
    ```

- [ ] **会话 ID 变量使用合理**：`${CLAUDE_SESSION_ID}` 用于适当场景
  - 验证方法：检查会话 ID 的使用场景是否合理
  - 适用场景：
    1. 日志记录：创建会话特定的日志文件
    2. 文件命名：生成会话唯一的输出文件
    3. 会话关联：将输出与会话关联
  - 错误示例：用于不需要会话区分的场景
  - 正确示例：
    ```yaml
    Log activity to logs/${CLAUDE_SESSION_ID}.log:
    $ARGUMENTS
    ```

- [ ] **工作量级别变量使用正确**：`${CLAUDE_EFFORT}` 用于适当场景
  - 验证方法：检查工作量级别变量的使用是否合理
  - 可用值：`low`、`medium`、`high`、`xhigh`、`max`
  - 适用场景：
    1. 根据工作量调整技能说明
    2. 在不同工作量下执行不同的逻辑
    3. 根据工作量控制输出详细程度
  - 错误示例：误用变量名如 `${CLAUDE_LEVEL}`
  - 正确示例：
    ```yaml
    # 根据当前工作量调整输出详细程度
    当前工作量级别为：${CLAUDE_EFFORT}。
    如果是 low 或 medium，提供简要总结。
    如果是 high、xhigh 或 max，提供详细分析。
    ```

- [ ] **技能目录变量使用正确**：`${CLAUDE_SKILL_DIR}` 用于正确的场景
  - 验证方法：检查技能目录变量的使用是否合理
  - 重要特性：插件技能指向插件内技能的子目录，不是插件根目录
  - 适用场景：
    1. 在 bash 注入命令中引用技能内置文件
    2. 无论当前工作目录如何都能正确解析脚本路径
  - 错误示例：使用硬编码路径
  - 正确示例：
    ```yaml
    Run the bundled script from the skill directory:
    ```bash
    python3 ${CLAUDE_SKILL_DIR}/scripts/helper.py --input data.json
    ```
    ```

- [ ] **字符串替换变量格式正确**：变量使用正确的语法格式
  - 验证方法：检查变量语法是否正确
  - 格式规则：
    1. `${VARIABLE}`：大写字母，下划线分隔，用 `${}` 包裹
    2. `$N`：单个数字索引，不用 `${}` 包裹
