# 1. 文档质量与最佳实践

文档质量与最佳实践检查确保技能有完整、清晰的文档，符合行业标准和推荐做法。

## 1.1 可维护性检查

### 1.1.1 复杂技能拆分
- [ ] **复杂技能拆分为附属文件** [警告]：超过500行的内容应拆分
  - 验证方法：检查主文件的长度
  - 拆分原则：
    - 主文件控制在500行以内
    - 详细文档移至参考文件
    - 示例移至 examples/ 目录
    - 脚本移至 scripts/ 目录

- [ ] **SKILL.md 主文件简洁** [可选项]：主文件应保持简洁
  - 验证方法：检查主文件的内容
  - 主文件应包含：
    - 前置元数据
    - 核心指令
    - 简要说明
    - 附属文件引用

### 1.1.2 使用示例
- [ ] **有必要的使用示例** [可选项]：复杂技能应提供使用示例
  - 验证方法：检查是否有示例
  - 示例类型：
    - 基本用法示例
    - 高级用法示例
    - 参数使用示例
    - 错误处理示例

- [ ] **示例覆盖主要场景** [可选项]：示例应覆盖主要使用场景
  - 验证方法：检查示例的覆盖面
  - 主要场景：
    - 常见使用场景
    - 边界情况
    - 错误场景

## 1.2 文档质量检查

### 1.2.1 自文档化
- [ ] **技能自包含** [警告]：技能不依赖外部硬依赖
  - 验证方法：检查是否有硬编码的外部依赖
  - 错误示例：硬编码的外部路径、URL
  - 正确示例：使用相对路径、变量

- [ ] **技能无外部硬依赖** [警告]：避免硬编码的外部依赖
  - 验证方法：检查是否有硬编码的路径、URL等
  - 错误示例：硬编码的绝对路径
  - 正确示例：使用相对路径或变量

### 1.2.2 内联注释
- [ ] **复杂逻辑有内联注释** [可选项]：复杂代码或逻辑应有注释
  - 验证方法：检查代码块的注释
  - 需要注释的情况：
    - 复杂的算法逻辑
    - 特殊的处理步骤
    - 重要的注意事项
    - 隐含的依赖关系

- [ ] **关键逻辑应有注释** [可选项]：关键逻辑应有注释
  - 验证方法：检查代码和复杂逻辑的注释
  - 需要注释的场景：
    - 复杂的条件判断
    - 特殊的数据处理
    - 重要的边界条件

### 1.2.3 参数说明
- [ ] **参数使用有明确说明** [必选项]：参数应有详细说明
  - 验证方法：检查参数的说明
  - 参数说明内容：
    - 参数含义
    - 参数类型
    - 必需/可选
    - 默认值
    - 示例值

## 1.3 示例完整性

### 1.3.1 使用示例
- [ ] **提供使用示例** [可选项]：复杂技能应提供示例
  - 验证方法：检查是否有示例部分
  - 示例内容：
    - 基本用法
    - 参数示例
    - 输出示例
    - 错误示例

- [ ] **示例可执行或说明清晰** [必选项]：示例应该是可运行的
  - 验证方法：测试示例的完整性
  - 错误示例：不完整的示例片段
  - 正确示例：完整、可执行的示例

### 1.3.2 示例覆盖面
- [ ] **示例覆盖主要使用场景** [可选项]：示例应具有代表性
  - 验证方法：检查示例的多样性
  - 应包含的示例：
    - 最常见的使用场景
    - 重要功能的使用方法
    - 典型参数的组合

## 1.4 错误处理

### 1.4.1 失败场景说明
- [ ] **有失败场景的说明** [可选项]：应说明可能的失败情况
  - 验证方法：检查是否有错误处理说明
  - 错误说明内容：
    - 常见错误类型
    - 错误原因
    - 解决方法

### 1.4.2 依赖条件说明
- [ ] **有依赖条件说明** [可选项]：应说明技能的前置条件
  - 验证方法：检查是否有依赖说明
  - 依赖说明内容：
    - 必需的工具
    - 必需的环境
    - 必需的配置
    - 必需的权限

## 1.5 代码结构检查

### 1.5.1 结构清晰性
- [ ] **技能结构清晰** [可选项]：技能应有清晰的章节划分
  - 验证方法：检查章节结构
  - 推荐结构：
    1. 技能描述（前置元数据）
    2. 技能说明（使用场景、注意事项）
    3. 执行流程（主要步骤）
    4. 参数说明（如有参数）
    5. 示例（使用示例）
    6. 故障排除（如有必要）
  - 错误示例：结构混乱，无清晰划分
  - 正确示例：结构清晰，层次分明

### 1.5.2 章节编号合理
- [ ] **章节编号合理** [可选项]：使用合理的章节编号
  - 验证方法：检查章节编号
  - 编号规则：
    - 使用 Markdown 标题层级（#、##、###）
    - 层级递进合理
    - 避免跳级
  - 错误示例：编号混乱，跳级严重
  - 正确示例：编号清晰，层次合理

## 1.6 可读性检查

### 1.6.1 语言表达清晰
- [ ] **语言表达清晰** [可选项]：使用清晰易懂的语言
  - 验证方法：检查语言的清晰度
  - 清晰度标准：
    - 避免使用模糊的词汇
    - 使用具体的描述
    - 避免过于专业的术语
    - 必要时添加术语解释
  - 错误示例：语言模糊，难以理解
  - 正确示例：语言清晰，易于理解

### 1.6.2 格式规范
- [ ] **格式规范统一** [可选项]：使用统一的格式规范
  - 验证方法：检查格式的一致性
  - 格式规范：
    - 标题格式一致
    - 列表格式一致
    - 代码块格式一致
    - 强调格式一致
  - 错误示例：格式混乱，不统一
  - 正确示例：格式统一，规范一致

## 1.7 可扩展性检查

### 1.7.1 易于扩展
- [ ] **技能易于扩展** [可选项]：设计应考虑未来扩展
  - 验证方法：评估扩展性
  - 扩展性特征：
    - 模块化设计
    - 功能分离
    - 参数化配置
    - 附属文件支持
  - 错误示例：耦合度高，难以扩展
  - 正确示例：模块化设计，易于扩展

### 1.7.2 版本控制建议
- [ ] **提供版本控制建议** [可选项]：说明如何进行版本管理
  - 验证方法：检查是否有版本说明
  - 版本管理建议：
    - 使用语义化版本号
    - 记录变更日志
    - 保持向后兼容
    - 提供迁移指南
  - 错误示例：无版本管理说明
  - 正确示例：
    ```markdown
    ## 版本管理

    本技能使用语义化版本号（SemVer）：
    - 主版本号：不兼容的 API 修改
    - 次版本号：向下兼容的功能性新增
    - 修订号：向下兼容的问题修正

    变更历史请参考 CHANGELOG.md
    ```
