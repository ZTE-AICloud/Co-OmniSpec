# 1. 内容质量增强检查

内容质量增强检查确保技能文档的质量、可操作性和符合最佳实践，提升用户体验和技能效果。

## 1.1 可操作性检查

### 1.1.1 可操作指导检查
- [ ] **skill 正文应包含可操作的指导（步骤、命令、检查清单）** [必选项]
  - 验证方法：检查技能正文是否包含编号步骤、要点指令、代码块或检查清单项
  - 检查内容：
    - 是否有明确的操作步骤
    - 是否有具体的命令示例
    - 是否有检查清单
    - 是否有决策流程
  - 错误示例：仅包含描述性段落而无指令性内容
  - 正确示例：
    ```markdown
    ## 重构流程

    1. **分析代码结构**
       - 使用 Glob 工具查找所有目标文件
       - 识别重复代码模式
       - 记录文件间的依赖关系

    2. **提取公共功能**
       - 创建新的工具函数文件
       - 将重复代码移至工具函数
       - 更新所有调用点

    3. **验证重构结果**
       - 运行完整测试套件
       - 检查功能完整性
       - 验证代码可读性提升
    ```
  - 自动修复：否

### 1.1.2 指令清晰性检查
- [ ] **操作指导应使用祈使动词** [必选项]
  - 验证方法：检查操作步骤是否使用祈使动词开头
  - 祈使动词示例：
    - 创建、读取、写入、删除
    - 分析、设计、实现、测试
    - 检查、验证、确认、提交
  - 错误示例："应该分析代码"（描述性）
  - 正确示例："分析代码结构"（祈使动词）
  - 自动修复：否

### 1.1.3 具体性检查
- [ ] **指导应具体而非模糊** [必选项]
  - 验证方法：检查指导是否包含具体的操作细节
  - 具体性标准：
    - 明确的工具名称和命令
    - 具体的文件路径和格式
    - 明确的参数和选项
    - 清晰的预期结果
  - 错误示例："分析代码"（过于模糊）
  - 正确示例："使用 Grep 工具查找所有包含 TODO 注释的文件"（具体）
  - 自动修复：否

## 1.2 字符串替换变量检查

### 1.2.1 正确替换语法检查
- [ ] **应使用官方替换变量语法** [必选项]
  - 验证方法：检查是否使用正确的替换变量
  - 官方支持的变量：
    - `$ARGUMENTS`：所有参数
    - `$ARGUMENTS[N]`：索引访问
    - `$N`：简写形式（$0, $1, $2...）
    - `${CLAUDE_SESSION_ID}`：会话 ID
    - `${CLAUDE_EFFORT}`：工作量级别
    - `${CLAUDE_SKILL_DIR}`：技能目录路径
  - 错误示例：使用临时占位符如 `<功能描述>`、`{{input}}`
  - 正确示例：使用官方替换变量
  - 自动修复：否

### 1.2.2 变量语法正确性
- [ ] **变量语法必须正确** [必选项]
  - 验证方法：检查变量语法的正确性
  - 语法规则：
    - `${VARIABLE}`：大写字母，下划线分隔
    - `$N`：单个数字索引，不用 `${}` 包裹
    - `$ARGUMENTS[N]`：数组索引访问
  - 错误示例：`$CLAUDE_SESSION_ID`（缺少花括号）、`${0}`（索引不应使用花括号）
  - 正确示例：`${CLAUDE_SESSION_ID}`、`$0`、`$ARGUMENTS[0]`
  - 自动修复：否

### 1.2.3 变量使用合理性
- [ ] **变量应在合适的场景使用** [可选项]
  - 验证方法：检查变量使用场景是否合理
  - 使用场景：
    - `$ARGUMENTS`：需要完整用户输入时
    - `$N`：需要特定位置的参数时
    - `${CLAUDE_SESSION_ID}`：会话专属资源时
    - `${CLAUDE_EFFORT}`：根据工作量调整逻辑时
    - `${CLAUDE_SKILL_DIR}`：引用技能内文件时
  - 错误示例：在不合适的场景使用变量
  - 正确示例：根据实际需求选择合适的变量
  - 自动修复：否

## 1.3 描述质量检查

### 1.3.1 描述长度限制检查
- [ ] **description + when_to_use 的总长度不应超过 250 个字符** [必选项]
  - 验证方法：如果 description 和 when_to_use 都存在，计算它们的总长度
  - 限制原因：中文文档中 skill 列表每条目限制为 250 字符
  - 错误示例：总长度超过 250 字符
  - 正确示例：
    ```yaml
    description: 分析代码结构，识别重构机会，执行安全重构操作
    when_to_use: 用户提到"重构"、"优化"、"代码质量"或需要改进代码时
    ```
  - 自动修复：否

### 1.3.2 描述前置重点检查
- [ ] **描述应前置关键用例（第一句说明最重要的触发场景）** [必选项]
  - 验证方法：检查描述的第一句是否清晰说明何时使用技能
  - 内容要求：
    - 第一句说明最重要的触发场景
    - 避免以背景信息或通用短语开头
    - 突出核心价值
  - 错误示例："这是一个有用的技能，可以帮助用户..."（前置了背景信息）
  - 正确示例："在需要重构代码时，分析代码结构并执行安全重构操作"（前置关键用例）
  - 自动修复：否

### 1.3.3 描述关键词检查
- [ ] **description 应包含高频场景关键词** [必选项]
  - 验证方法：检查描述中是否包含相关的领域关键词
  - 关键词作用：
    - 帮助 Claude 识别触发场景
    - 提高自动触发准确性
    - 帮助用户理解技能用途
  - 错误示例：描述过于泛化，缺乏关键词
  - 正确示例：
    ```yaml
    description: 分析代码结构，识别重构机会，执行安全重构。适用于重构、代码优化、代码质量改进等场景。
    ```
  - 自动修复：否

## 1.4 副作用配置检查

### 1.4.1 disable-model-invocation 配置检查
- [ ] **有副作用的任务型 skill 应设置 'disable-model-invocation: true'（除非被其他 skill 调用）** [必选项]
  - 验证方法：检查技能正文包含有副作用的操作时，frontmatter 是否有相应配置
  - 有副作用的操作：
    - 部署操作
    - 提交代码（git commit、push）
    - 发送消息或邮件
    - 删除文件或数据
    - 修改生产环境配置
  - **例外情况：如果被其他 skill 调用，不能设置 true**
  - 错误示例：包含 git push 但未设置 disable-model-invocation
  - 正确示例：
    ```yaml
    ---
    name: deploy-production
    description: 部署应用到生产环境
    disable-model-invocation: true  # 不被其他技能调用时
    ---
    ```
  - 被调用时的正确示例：
    ```yaml
    ---
    name: base-deploy-helper
    description: 部署基础能力，被上层部署技能调用
    # 虽然涉及部署操作，但被其他技能调用，不能设置 true
    ---
    ```
  - 自动修复：否

### 1.4.2 无副作用技能配置检查
- [ ] **无副作用的参考类技能不应设置 disable-model-invocation: true** [必选项]
  - 验证方法：检查技能内容与配置的一致性
  - 无副作用技能特征：
    - 代码规范说明
    - 业务领域知识
    - 设计模式解释
    - API 文档参考
  - 错误示例：纯参考类技能设置了 disable-model-invocation
  - 正确示例：参考类技能使用默认配置或 false
  - 自动修复：否

### 1.4.3 被调用技能配置检查
- [ ] **被其他 skill 调用的技能不能设置 disable-model-invocation: true** [必选项]
  - 验证方法：检查技能是否被其他技能调用（通过 agent 配置、预加载等）
  - 调用场景：
    - 作为子代理预加载的技能
    - 被其他技能通过 Agent 工具调用
    - 提供基础能力的工具类技能
  - 错误示例：被调用的技能设置了 disable-model-invocation: true（会导致调用失败）
  - 正确示例：
    ```yaml
    ---
    name: code-analyzer
    description: 代码分析基础能力，被多个技能调用
    # 允许自动调用
    ---
    ```
  - 自动修复：否

### 1.4.4 敏感信息安全检查
- [ ] **技能内容不包含明文密码** [必选项]：禁止在技能中包含任何明文密码、密钥等敏感信息
  - 验证方法：检查技能正文和元数据中是否包含敏感信息
  - 敏感信息类型：
    - 密码类：`password`、`passwd`、`pwd` 等字段的明文值
    - 密钥类：API Key、Secret Key、Access Token、Private Key
    - 认证类：Bearer Token、OAuth Token、Session ID
    - 数据库连接串：包含明文密码的连接字符串
    - 其他敏感信息：SSH 密钥、加密密钥、认证凭据
  - 错误示例：包含明文密码、API 密钥等
  - 正确示例：使用环境变量或占位符（如 `${DB_PASSWORD}`）
  - 处理要求：
    - 必须立即移除所有明文密码和敏感信息
    - 使用环境变量、占位符或外部配置文件替代
    - 如果意外提交，应立即撤销并重新生成凭据
  - 自动修复：否（必须手动移除并重新生成凭据）

## 1.5 技能目录引用检查

### 1.5.1 CLAUDE_SKILL_DIR 使用检查
- [ ] **引用脚本或自身目录中文件的 skill 应使用 ${CLAUDE_SKILL_DIR}** [必选项]
  - 验证方法：检查技能正文通过相对路径引用脚本/文件时是否使用了正确变量
  - 重要特性：
    - 确保路径无论当前工作目录如何都能正常工作
    - 插件技能指向插件内技能的子目录
    - 不是插件根目录
  - 错误示例：使用相对路径如 `scripts/validate.sh`、`./helper.py`
  - 正确示例：
    ```bash
    python3 ${CLAUDE_SKILL_DIR}/scripts/analyze.py
    ```
  - 自动修复：否

### 1.5.2 路径构建正确性
- [ ] **${CLAUDE_SKILL_DIR} 路径构建应正确** [必选项]
  - 验证方法：检查路径拼接是否正确
  - 路径构建规则：
    - 使用正确的路径分隔符（/）
    - 避免多余的斜杠
    - 避免缺少必要的斜杠
  - 错误示例：
    - `${CLAUDE_SKILL_DIR}scripts/helper.sh`（缺少斜杠）
    - `${CLAUDE_SKILL_DIR}//scripts/helper.sh`（多余斜杠）
  - 正确示例：
    - `${CLAUDE_SKILL_DIR}/scripts/helper.sh`（正确）
  - 自动修复：否
