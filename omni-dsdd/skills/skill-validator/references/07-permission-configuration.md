# 1. 权限配置检查

权限配置控制技能如何被触发和使用，以及技能可以访问哪些工具。这是技能安全性和可用性的重要保障。

## 1.1 调用权限检查

### 1.1.1 disable-model-invocation 字段
- [ ] **disable-model-invocation 设置合理** [必选项]：根据技能类型、风险等级和调用关系正确设置
  - 验证方法：分析技能的功能、风险等级和是否被其他 skill 调用
  - 配置逻辑：
    - **被其他 skill 调用的技能（必须 false 或省略）**：
      - 作为子代理预加载的技能
      - 被其他技能通过 Agent 工具调用的技能
      - 提供基础能力的工具类技能
      - 正确示例：
        ```yaml
        ---
        name: code-analyzer
        description: 代码分析基础能力，被多个技能调用
        disable-model-invocation: false  # 必须允许自动调用
        ---
        ```
      - 错误示例：
        ```yaml
        ---
        name: code-analyzer
        description: 代码分析基础能力
        disable-model-invocation: true  # 错误！被其他技能调用时无法自动触发
        ---
        ```
      - 检查方法：
        - 查看技能是否被其他技能的 `agent:` 字段引用
        - 查看技能是否作为子代理的预加载技能
        - 查看技能内容是否被其他技能调用

    - **高风险技能（建议 true）**：
      - 部署类技能（部署到生产环境）
      - 提交代码类技能（git commit, git push）
      - 数据修改类技能（数据库操作）
      - 外部 API 调用类技能（发送消息、邮件）
      - 文件删除类技能（rm, 删除操作）

    - **低风险技能（建议 false 或省略）**：
      - 代码解释类技能
      - 代码生成类技能
      - 参考文档类技能
      - 代码审查类技能
      - 格式化类技能

- [ ] **高风险技能必须设置 true** [必选项]：有副作用的技能必须禁止自动调用
  - 验证方法：检查技能是否包含高风险操作
  - 错误示例：部署技能允许自动调用
  - 正确示例：
    ```yaml
    ---
    name: deploy-production
    description: 将应用部署至生产环境
    disable-model-invocation: true  # 必须手动触发
    ---
    ```

- [ ] **被其他 skill 调用的技能不能设置 true** [必选项]：确保调用链正常
  - 验证方法：检查技能是否被其他技能调用
  - 调用关系识别：
    - 检查其他技能的 `agent:` 配置
    - 检查其他技能的内容是否调用此技能
    - 检查是否作为子代理的预加载技能
  - 错误示例：被调用的技能禁止自动调用
  - 正确示例：
    ```yaml
    ---
    name: base-analyzer
    description: 基础分析能力，被多个上层技能调用
    # 不设置 disable-model-invocation，允许被自动调用
    ---
    ```

- [ ] **布尔值格式正确** [必选项]：使用 true/false
  - 验证方法：检查布尔值格式
  - 错误示例：`yes`、`no`、`on`、`off`
  - 正确示例：`true`、`false`

### 1.1.2 user-invocable 字段
- [ ] **user-invocable 设置合理** [必选项]：根据技能用途正确设置
  - 验证方法：分析技能是否需要用户手动触发
  - 配置逻辑：
    - **后台技能（建议 false）**：
      - 纯知识类技能（代码规范、业务知识）
      - 背景信息提供技能
      - 上下文注入技能
      - 配置信息技能

    - **交互技能（建议 true 或省略）**：
      - 需要用户确认的操作
      - 需要用户提供参数的操作
      - 需要用户决策的操作
      - 常规任务类技能

- [ ] **后台技能设置 false** [可选项]：纯知识类技能应隐藏用户调用入口
  - 验证方法：检查技能是否为纯知识提供
  - 错误示例：代码规范技能允许用户调用
  - 正确示例：
    ```yaml
    ---
    name: project-standards
    description: 本项目代码规范和最佳实践
    user-invocable: false  # 仅后台自动加载
    ---
    ```

## 1.2 权限与描述一致性检查

### 1.2.1 description 与配置一致性
- [ ] **description 描述的调用方式与实际配置一致** [必选项]：描述应准确反映配置
  - 验证方法：比较 description 中的调用方式和实际配置
  - 错误示例：
    ```yaml
    ---
    description: 用户可以通过 /deploy 手动部署应用
    disable-model-invocation: false  # 描述说手动调用，但允许自动调用
    ---
    ```
  - 正确示例：
    ```yaml
    ---
    description: 用户可以通过 /deploy 手动部署应用，禁止自动触发
    disable-model-invocation: true  # 配置与描述一致
    ---
    ```

- [ ] **description 包含触发条件** [必选项]：描述应说明触发条件
  - 验证方法：检查 description 是否说明何时触发
  - 错误示例：缺少触发条件说明
  - 正确示例：
    ```yaml
    ---
    description: 当用户询问代码规范时自动触发，提供项目编码标准说明
    ---
    ```

### 1.2.2 allowed-tools 与技能需求匹配
- [ ] **allowed-tools 与技能需求匹配** [必选项]：配置的工具应与技能实际需要一致
  - 验证方法：检查技能内容中使用的工具
  - 错误示例：
    ```yaml
    ---
    allowed-tools: Read  # 只允许读操作
    ---
    技能内容中包含写入操作...
    ```
  - 正确示例：
    ```yaml
    ---
    allowed-tools: Read, Write, Edit  # 允许读写操作
    ---
    技能内容包含读写操作...
    ```

### 1.2.3 权限配置矛盾检查
- [ ] **无矛盾配置** [必选项]：检查权限配置是否存在逻辑矛盾
  - 验证方法：分析各项权限配置的关系
  - 典型矛盾配置：
    - `disable-model-invocation: true` 且 `user-invocable: false`
      - 含义：既禁止自动调用，又禁止用户调用
      - 结果：技能永远无法被调用
  - 错误示例：
    ```yaml
    ---
    disable-model-invocation: true
    user-invocable: false
    ---
    ```
  - 正确示例：
    ```yaml
    ---
    disable-model-invocation: true
    user-invocable: true  # 允许用户手动调用
    ---
    ```

## 1.3 工具权限检查

### 1.3.1 工具列表合理性检查
- [ ] **工具名称拼写正确**：确保工具名称准确无误
  - 验证方法：对照官方工具名称列表检查
  - 常用工具列表：
    - **文件操作**：`Read`、`Write`、`Edit`
    - **搜索操作**：`Grep`、`Glob`
    - **系统操作**：`Bash`
    - **代理操作**：`Agent`
    - **任务操作**：`TaskCreate`、`TaskUpdate`、`TaskList`
    - **交互操作**：`AskUserQuestion`
    - **计划操作**：`EnterPlanMode`、`ExitPlanMode`
    - **Git操作**：通过 Bash 执行 git 命令

- [ ] **工具名称首字母大写**：工具名称应使用正确的驼峰命名
  - 验证方法：检查工具名称的大小写
  - 错误示例：`read`、`grep`、`bash`
  - 正确示例：`Read`、`Grep`、`Bash`

- [ ] **列出的工具确实是技能必需的**：只配置必需的工具
  - 验证方法：分析技能内容，确定实际需要的工具
  - 错误示例：配置了技能从未使用的工具
  - 正确示例：只配置技能实际使用的工具

- [ ] **工具配置覆盖所有需求**：确保技能需要的所有工具都已配置
  - 验证方法：检查技能内容中的操作需求
  - 错误示例：技能需要写入文件但未配置 Write 工具
  - 正确示例：所有需要的工具都已配置

### 1.3.2 Bash 工具权限详细检查
- [ ] **Bash 权限必要性检查**：只有在需要执行命令时才配置
  - 验证方法：检查技能是否包含命令执行需求
  - 需要Bash的场景：
    - 运行测试命令（npm test, pytest）
    - 执行构建命令（npm run build, make）
    - Git操作（git add, git commit）
    - 系统操作（ls, find, grep）
    - 脚本执行（./scripts/setup.sh）

- [ ] **不必要的 Bash 权限**：不需要命令执行的技能不应配置 Bash
  - 验证方法：检查技能是否真的需要执行命令
  - 错误示例：纯代码解释技能配置了 Bash 权限
  - 正确示例：只在需要时配置 Bash 权限

- [ ] **Bash 权限使用命令白名单**：限制可执行的命令范围
  - 验证方法：检查是否配置了命令白名单
  - 推荐做法：使用 `Bash(command1, command2, ...)` 格式
  - 错误示例：
    ```yaml
    allowed-tools: Bash  # 允许执行所有命令
    ```
  - 正确示例：
    ```yaml
    allowed-tools: Bash(ls, test, find)  # 只允许特定命令
    ```

- [ ] **命令白名单合理性**：白名单中的命令都是必需的
  - 验证方法：检查每个命令的必要性
  - 常用白名单命令：
    - `ls`：列出文件
    - `test`：测试条件
    - `find`：查找文件
    - `cat`：查看文件
    - `echo`：输出文本
    - `mkdir`：创建目录
    - `chmod`：修改权限

- [ ] **避免危险命令** [必选项]：不应允许执行危险命令
  - 验证方法：检查白名单中是否包含危险命令
  - 危险命令示例：
    - `rm`：删除文件
    - `mv`：移动文件（可能导致数据丢失）
    - `sudo`：提升权限
    - `dd`：直接磁盘操作
    - `mkfs`：文件系统操作

- [ ] **危险命令有额外保护** [必选项]：如果必须使用危险命令，应有额外保护
  - 验证方法：检查是否有保护措施
  - 保护措施：
    - 禁用危险命令
    - 添加确认步骤
    - 提供回滚机制
    - 限制参数范围

## 1.4 权限最小化原则检查

### 1.4.1 只读技能权限
- [ ] **只读技能限制为读操作** [必选项]：只读技能应只配置读相关工具
  - 验证方法：检查技能是否为只读性质
  - 典型只读技能：
    - 代码解释器
    - 代码审查器
    - 文档生成器
    - 信息查询器
  - 正确配置：
    ```yaml
    allowed-tools: Read, Grep, Glob
    ```

- [ ] **只读技能禁止写入权限** [必选项]：只读技能不应有 Write、Edit 权限
  - 验证方法：检查只读技能的权限配置
  - 错误示例：
    ```yaml
    # 只读技能配置了写入权限
    allowed-tools: Read, Grep, Write, Edit
    ```
  - 正确示例：
    ```yaml
    # 只读技能只配置读权限
    allowed-tools: Read, Grep, Glob
    ```

### 1.4.2 读写技能权限
- [ ] **读写技能配置必要的读写权限** [必选项]：根据需要配置读写工具
  - 验证方法：检查技能的读写需求
  - 读写工具选择：
    - `Read`：读取文件内容
    - `Write`：写入新文件
    - `Edit`：编辑现有文件
  - 错误示例：需要编辑但只配置了 Write
  - 正确示例：根据实际需求配置

### 1.4.3 搜索权限配置
- [ ] **搜索权限配置合理** [必选项]：根据搜索需求配置
  - 验证方法：检查技能的搜索需求
  - 搜索工具选择：
    - `Grep`：内容搜索（按内容搜索文件）
    - `Glob`：文件搜索（按名称模式搜索文件）
  - 使用场景：
    - 只需要文件名搜索：只配置 Glob
    - 只需要内容搜索：只配置 Grep
    - 需要两种搜索：同时配置 Glob 和 Grep

## 1.5 不同类型技能的权限配置建议

### 1.5.1 参考类技能
- [ ] **参考类技能配置建议**：
  - `disable-model-invocation: false` 或省略（允许自动加载）
  - `user-invocable: false`（隐藏用户调用入口）
  - `allowed-tools: Read`（通常只需要读权限）
  - 示例：
    ```yaml
    ---
    name: coding-standards
    description: 项目编码规范和最佳实践，当编写或审查代码时自动加载
    user-invocable: false
    allowed-tools: Read
    ---
    ```

### 1.5.2 任务类技能
- [ ] **任务类技能配置建议**：
  - `disable-model-invocation: true`（禁止自动调用，**除非被其他技能调用**）
  - `user-invocable: true` 或省略（允许用户手动调用）
  - `allowed-tools: 根据需要配置`（根据实际需求配置）
  - 示例：
    ```yaml
    ---
    name: deploy-production
    description: 将应用部署至生产环境
    disable-model-invocation: true  # 不被其他技能调用时
    allowed-tools: Read, Write, Bash
    ---
    ```
  - 被调用时的示例：
    ```yaml
    ---
    name: base-deploy-helper
    description: 部署基础能力，被上层技能调用
    # 虽然涉及部署，但被调用，不能设置 true
    ---
    ```

### 1.5.3 工具类技能
- [ ] **工具类技能配置建议**：
  - `disable-model-invocation: false`（允许自动调用）
  - `user-invocable: true`（允许用户手动调用）
  - `allowed-tools: 根据需要配置`（根据实际需求配置）
  - 示例：
    ```yaml
    ---
    name: code-formatter
    description: 格式化代码，当代码不符合规范时自动触发
    allowed-tools: Read, Write, Edit
    ---
    ```

### 1.5.4 代码解释类技能
- [ ] **代码解释类技能工具配置**：
  - 必需工具：`Read`（读取代码）
  - 可选工具：`Grep`（搜索相关代码）、`Glob`（查找相关文件）
  - 禁止工具：`Write`、`Edit`、`Bash`（不应修改代码）
  - 示例配置：
    ```yaml
    allowed-tools: Read, Grep, Glob
    ```

### 1.5.5 代码生成类技能
- [ ] **代码生成类技能工具配置**：
  - 必需工具：`Read`（读取上下文）、`Write`（生成代码）
  - 可选工具：`Edit`（编辑现有代码）、`Grep`（搜索现有代码）
  - 慎用工具：`Bash`（除非需要执行构建、测试）
  - 示例配置：
    ```yaml
    allowed-tools: Read, Write, Edit, Grep
    ```

### 1.5.6 部署类技能
- [ ] **部署类技能工具配置**：
  - 必需工具：`Read`（读取配置）、`Bash`（执行部署命令）
  - 可选工具：`Write`（生成配置文件）、`Grep`（检查状态）
  - 注意事项：
    - Bash 命令应使用白名单
    - 避免危险的删除命令
  - 示例配置：
    ```yaml
    allowed-tools: Read, Write, Bash(npm, git, ls, cat)
    ```

### 1.5.7 测试类技能
- [ ] **测试类技能工具配置**：
  - 必需工具：`Read`（读取测试用例）、`Bash`（运行测试）
  - 可选工具：`Grep`（搜索测试相关代码）、`Glob`（查找测试文件）
  - 示例配置：
    ```yaml
    allowed-tools: Read, Grep, Glob, Bash(npm, pytest, python)
    ```

## 1.6 权限配置最佳实践

### 1.6.1 最小权限原则
- [ ] **遵循最小权限原则** [必选项]：只授予必要的权限
  - 验证方法：检查配置的权限是否都是必需的
  - 原则：如果技能不需要某个权限，就不要配置
  - 错误示例：只读技能配置了写入权限
  - 正确示例：
    ```yaml
    ---
    name: code-explainer
    description: 解释代码工作原理
    allowed-tools: Read  # 只需要读权限
    ---
    ```

### 1.6.2 权限说明文档化
- [ ] **权限配置有说明** [可选项]：复杂的权限配置应有说明
  - 验证方法：检查技能文档中是否有权限说明
  - 错误示例：复杂权限配置无任何说明
  - 正确示例：
    ```yaml
    ---
    # 只允许读取和搜索，禁止修改操作
    # 原因：本技能用于代码审查，不应修改代码
    allowed-tools: Read, Grep, Glob
    ---
    ```

### 1.6.3 安全性考虑
- [ ] **高风险操作有多重保护** [必选项]：重要操作应有额外的保护措施
  - 验证方法：检查高风险技能的保护措施
  - 保护措施：
    - 禁止自动调用
    - 需要用户确认
    - 添加确认提示
    - 提供回滚机制
  - 错误示例：删除操作技能无任何保护
  - 正确示例：
    ```markdown
    # 删除文件流程

    1. 确认要删除的文件列表
    2. 向用户确认删除操作
    3. 执行删除操作
    4. 记录删除日志（便于回滚）
    ```

### 1.6.4 权限越界检查
- [ ] **无权限越界** [必选项]：确保技能配置的权限在其功能范围内
  - 验证方法：比较技能功能描述和权限配置
  - 错误示例：简单的文本处理技能配置了 Bash 权限
  - 正确示例：权限配置与技能功能范围一致

### 1.6.5 权限分离检查
- [ ] **高风险操作权限分离** [可选项]：高风险操作应有单独的技能
  - 验证方法：检查是否将高风险操作混在一般技能中
  - 错误示例：代码审查和代码删除在同一个技能中
  - 正确示例：高风险操作（如删除）单独配置技能

### 1.6.6 权限文档化
- [ ] **权限配置有文档说明** [可选项]：复杂的权限配置应有说明
  - 验证方法：检查技能文档中是否有权限说明
  - 错误示例：复杂权限配置无任何说明
  - 正确示例：
    ```markdown
    ## 权限说明

    本技能需要以下工具权限：
    - Read：读取源代码和配置文件
    - Write：生成新的代码文件
    - Edit：修改现有代码
    - Grep：搜索相关的代码和文档

    注意：本技能不会执行任何系统命令（无 Bash 权限）
    ```

### 1.6.7 敏感信息安全检查
- [ ] **技能内容不包含明文密码** [必选项]：禁止在技能中包含任何明文密码、密钥等敏感信息
  - 验证方法：检查技能正文和元数据中是否包含敏感信息
  - 敏感信息类型：
    - **密码类**：`password`、`passwd`、`pwd` 等字段的明文值
    - **密钥类**：API Key、Secret Key、Access Token、Private Key
    - **认证类**：Bearer Token、OAuth Token、Session ID
