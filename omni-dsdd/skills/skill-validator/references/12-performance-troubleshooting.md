# 1. 性能与故障排除

检查技能的性能影响和故障排除能力，确保技能高效且问题可解决。

## 1.1 字符配额检查

### 1.1.1 description 长度检查
- [ ] **description 长度合理** [可选项]：description 应控制在合理范围内
  - 验证方法：检查 description 字符数
  - 建议：100-200 字符
  - 影响：技能简介会占用上下文字符配额
  - 错误示例：description 过长（>300 字符）
  - 正确示例：简洁明了的 description

- [ ] **description 对配额影响说明** [可选项]：说明对上下文配额的影响
  - 验证方法：评估 description 的影响
  - 说明内容：
    - 技能简介占用上下文字符配额
    - 技能过多可能被自动截断
    - 默认配额为上下文窗口的 2%
    - 最低保底 16000 字符

### 1.1.2 技能数量检查
- [ ] **评估技能总数** [可选项]：评估技能数量对配额的影响
  - 验证方法：统计技能总数
  - 影响：技能越多，占用配额越多
  - 风险：技能过多会被自动截断屏蔽
  - 建议：合理控制技能数量，合并相似技能

- [ ] **提供字符配额建议** [可选项]：提供优化字符配额的建议
  - 优化方法：
    - 精简 description
    - 合并相似技能
    - 移除不常用的技能
    - 使用环境变量 SLASH_COMMAND_TOOL_CHAR_BUDGET 自定义配额

## 1.2 故障排除检查

### 1.2.1 故障排除章节
- [ ] **包含故障排除章节** [可选项]：技能应包含故障排除说明
  - 验证方法：检查是否有故障排除章节
  - 适用技能：复杂技能、有外部依赖的技能
  - 错误示例：复杂技能无故障排除说明
  - 正确示例：
    \`\`\`markdown
    ## 故障排除

    ### 常见问题

    **问题 1：技能无法触发**
    - 原因：description 描述不够具体
    - 解决：优化 description，补充关键词

    **问题 2：命令执行失败**
    - 原因：缺少必要的依赖工具
    - 解决：安装所需的依赖工具
    \`\`\`

- [ ] **覆盖常见问题** [可选项]：应列出用户可能遇到的常见问题
  - 验证方法：检查常见问题的完整性
  - 常见问题类型：
    - 技能无法触发
    - 技能过度触发
    - 命令执行失败
    - 权限不足
    - 依赖缺失
  - 错误示例：常见问题覆盖不全
  - 正确示例：覆盖主要的常见问题

  - 验证方法：检查排查步骤的逻辑性
  - 排查步骤特征：
    - 从简单到复杂
    - 从常见到罕见
    - 每步都有明确的目标
  - 错误示例：排查步骤混乱
  - 正确示例：
    \`\`\`markdown
    **问题排查步骤：**

    1. 检查技能是否正常加载
    2. 验证环境依赖是否安装
    3. 检查权限配置是否正确
    4. 查看错误日志获取详细信息
    5. 参考文档或联系支持
    \`\`\`

- [ ] **提供错误信息解读** [可选项]：应说明常见错误信息的含义
  - 验证方法：检查错误信息的解释
  - 错误信息类型：
    - 技能加载失败
    - 命令执行错误
    - 权限拒绝
    - 依赖缺失
  - 错误示例：无错误信息解读
  - 正确示例：
    \`\`\`markdown
    **常见错误信息：**

    - "技能未找到"：检查技能路径和名称
    - "权限拒绝"：检查技能的权限配置
    - "命令不存在"：检查系统依赖是否安装
    \`\`\`

### 1.2.3 解决方案提供
- [ ] **解决方案具体可操作** [必选项]：提供具体的解决方案
  - 验证方法：检查解决方案的可操作性
  - 解决方案特征：
    - 有明确的步骤
    - 有具体的命令
    - 有预期的结果
  - 错误示例：解决方案模糊不清
  - 正确示例：
    \`\`\`markdown
    **解决方案：安装缺失的依赖**

    1. 检查是否安装了 gh CLI：
       \`\`\`bash
       gh --version
       \`\`\`

    2. 如果未安装，运行以下命令：
       \`\`\`bash
       # macOS
       brew install gh

       # Linux
       curl -fsSL https://cli.github.com/packages/githubcli-archive-keyring.gpg | sudo dd of=/usr/share/keyrings/githubcli-archive-keyring.gpg
       \`\`\`

    3. 配置 GitHub 认证：
       \`\`\`bash
       gh auth login
       \`\`\`

    4. 验证安装：
       \`\`\`bash
       gh --version
       \`\`\`
    \`\`\`

- [ ] **提供备选方案** [可选项]：为主要问题提供备选解决方案
  - 验证方法：检查是否有备选方案
  - 备选方案场景：
    - 主要方案失败时
    - 特定环境不支持时
    - 权限受限时
  - 错误示例：无备选方案
  - 正确示例：
    \`\`\`markdown
    **备选方案：手动获取信息**

    如果 gh CLI 不可用，可以手动获取拉取请求信息：

    1. 访问 GitHub 网页界面
    2. 查看拉取请求的 "Files changed" 标签
    3. 复制需要的变更信息
    \`\`\`

## 1.3 性能优化检查

### 1.3.1 上下文使用效率
- [ ] **上下文使用效率优化** [可选项]：技能应高效使用上下文资源
  - 验证方法：检查技能的上下文消耗
  - 优化建议：
    - 避免加载不必要的内容
    - 使用精确的触发条件
    - 限制附属文件的加载范围
  - 错误示例：技能加载大量无关内容
  - 正确示例：按需加载，精确触发

### 1.3.2 Token消耗评估
- [ ] **Token消耗合理** [可选项]：技能的Token消耗应在合理范围
  - 验证方法：评估技能执行过程中的Token使用
  - 考虑因素：
    - description 和 when_to_use 的长度
    - 引用的附属文件大小
    - 执行过程中生成的文本量
  - 错误示例：单次执行消耗过多Token
  - 正确示例：合理控制Token消耗

### 1.3.3 性能瓶颈识别
- [ ] **识别潜在的性能瓶颈** [可选项]：检查技能可能的性能问题
  - 验证方法：分析技能的执行流程
  - 常见性能瓶颈：
    - 大量文件读取操作
    - 复杂的搜索和遍历
    - 不必要的重复操作
    - 缺乏结果缓存
  - 错误示例：存在明显的性能问题
  - 正确示例：无明显性能瓶颈

### 1.3.4 性能优化建议
- [ ] **提供性能优化建议** [可选项]：给出改进技能性能的建议
  - 优化方向：
    - 优化文件读取策略
    - 减少不必要的操作
    - 使用缓存机制
    - 优化搜索和匹配算法
  - 错误示例：无性能相关建议
  - 正确示例：
    \`\`\`markdown
    ## 性能优化建议

    - 优先使用 Glob 而非递归搜索
    - 限制搜索的文件范围
    - 避免重复读取相同文件
    - 使用更高效的匹配算法
    \`\`\`

## 1.4 错误处理机制

### 1.4.1 异常情况处理
- [ ] **有异常情况处理说明** [必选项]：应说明如何处理异常情况
  - 验证方法：检查是否有异常处理说明
  - 异常情况类型：
    - 文件不存在
    - 权限不足
    - 命令执行失败
    - 依赖缺失
  - 错误示例：无异常处理说明
  - 正确示例：
    \`\`\`markdown
    ## 异常处理

    如果遇到文件不存在的情况：
    1. 检查文件路径是否正确
    2. 验证文件是否被移动或删除
    3. 提供创建缺失文件的建议
    \`\`\`

### 1.4.2 失败回退机制
- [ ] **有失败回退机制** [必选项]：重要操作应有回退机制
  - 验证方法：检查是否有回退策略
  - 回退机制特征：
    - 提供回滚步骤
    - 记录操作历史
    - 保存原始状态
  - 错误示例：无回退机制
  - 正确示例：
    \`\`\`markdown
    ## 回退机制

    如果部署失败，执行回退：
    1. 保留原始部署版本
    2. 回滚到上一个稳定版本
    3. 通知相关人员
    \`\`\`

### 1.4.3 错误友好性
- [ ] **错误信息友好易懂** [必选项]：错误提示应清晰易懂
  - 验证方法：检查错误信息的表述
  - 友好性特征：
    - 使用用户易懂的语言
    - 提供具体的问题描述
    - 给出明确的解决建议
  - 错误示例：错误信息模糊，难以理解
  - 正确示例：
    \`\`\`markdown
    **错误：依赖工具未安装**

    缺少必要的依赖工具：gh CLI
    安装方法：
    - macOS: brew install gh
    - Linux: 参考官方安装指南
    \`\`\`
