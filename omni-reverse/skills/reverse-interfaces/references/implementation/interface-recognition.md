# 接口识别Skill（默认）

## Overview

通用的接口识别skill，用于从单个代码文件中识别接口。接收目标文件路径（`file_path`），分析该文件中的所有代码，识别出文件中定义的所有接口（RESTful API端点、CLI命令处理函数、函数接口等）。结合LSP工具、模式匹配、Few-shot示例和业务语义分析等多种方式，能够从目标文件中准确识别各种类型的接口。

## 输入参数

- **file_path** (必需): 目标文件路径（绝对路径），要被识别接口的源代码文件
- **interface_types_file** (必需): interface-types.json文件路径，包含需要识别的接口类型列表
- **constraints_file** (可选): constraints.json文件路径，包含用户配置的约束规则
- **interface_patterns_file** (必需): interface-patterns.json文件路径，包含接口模式特征
- **few_shot_examples_file** (必需): few-shot-examples.json文件路径，包含Few-shot示例集合
- **output_file** (必需): 临时输出文件路径（绝对路径），Skill将识别到的接口写入此文件

## 输出格式

🔴 **重要**：Skill不再返回接口数组，而是直接写入文件，以减少与SubAgent的交互内容，避免上下文超限。

### 文件输出格式

Skill将识别到的接口直接写入`output_file`指定的临时文件，文件内容为JSON数组格式：

```json
[
  {
    "name": "getUserInfo",
    "business_name": "根据用户ID获取用户信息",
    "business_domain": "用户管理",
    "business_function": "查询用户信息",
    "interface_type": "RESTful API",
    "source_file": "/path/to/controllers/user.controller.js",
    "path_method": "/api/users/{id} GET",
    "parameters": [...],
    "returns": {...},
    "description": "根据用户ID获取用户详细信息",
    "module": "user-service",
    "layer": "controller",
    "language": "JavaScript",
    "confidence": 0.95,
    "tags": ["user", "profile"],
    "annotations": ["@GetMapping", "@ApiOperation"]
  }
]
```

### Skill返回格式（极简JSON）

Skill执行完成后，向SubAgent返回极简状态JSON，不包含接口数据：

**成功时**：
```json
{"ok": true, "count": 5}
```

**失败时**：
```json
{"ok": false, "error": "文件读取失败"}
```

**注意**：
- 如果文件中没有识别到接口，写入空数组 `[]`，返回 `{"ok": true, "count": 0}`
- `interface_id` 由调用方（subagent）统一生成，skill不需要生成
- `source_file` 应只包含当前文件路径
- 所有字段都是必需的，如果无法确定某个字段的值，应使用合理的默认值
- 🔴 **强制要求**：必须确保输出文件已成功写入，如果写入失败，返回 `{"ok": false, "error": "文件写入失败"}`

## Workflow

### 0. [ ] 创建接口识别任务的Todo列表

- [ ] **步骤1 读取规则和特征文件**
- [ ] **步骤2 分析目标文件**
- [ ] **步骤3 接口识别和分类**
- [ ] **步骤4 生成接口对象**
- [ ] **步骤5 写入输出文件**
- [ ] **步骤6 返回执行结果**

### 1. [ ] 读取规则和特征文件

- 读取 `interface_types_file`，获取需要识别的接口类型列表
- 读取 `interface_patterns_file`，获取接口模式特征
- 读取 `few_shot_examples_file`，获取Few-shot示例
- 如果提供了 `constraints_file`，读取约束规则
- 验证所有规则文件是否存在且可访问

### 2. [ ] 分析目标文件

从`file_path`指定的目标文件中识别所有接口定义。

**子任务Todo列表：**
- [ ] **2.1 Token检查和目标文件验证**
- [ ] **2.2 文件类型判断**
- [ ] **2.3 LSP工具使用（如果支持）**
- [ ] **2.4 模式匹配**
- [ ] **2.5 业务语义提取**

#### 2.1. [ ] Token检查和目标文件验证

- 🔴 **强制Token检查**：处理目标文件前必须检查当前上下文大小，如超过10万tokens则强制清空
- 🔴 **目标文件验证**：验证目标文件是否存在且可读
- 如果目标文件不存在或无法读取，写入空数组 `[]` 到输出文件，返回 `{"ok": false, "error": "目标文件不存在或无法读取: {file_path}"}`

#### 2.2. [ ] 文件类型判断

- 根据`file_path`的文件扩展名判断编程语言（如`.py`、`.js`、`.java`、`.go`等）
- 确定是否支持LSP工具

#### 2.3. [ ] LSP工具使用（如果支持）

- 如果目标文件语言支持LSP工具，使用LSP工具进行精确识别：
  - 使用 `documentSymbol` 获取目标文件内的所有符号信息
  - 从符号列表中筛选出接口相关符号
  - 使用 `hover` 获取每个接口符号的文档和类型信息
  - 使用 `findReferences` 了解接口符号的调用关系
  - 使用 `goToDefinition` 获取接口符号的完整定义上下文
- 🔴 **精确指定信息**：调用LSP工具时必须明确指定目标文件路径、函数名等精确信息
- 🔴 **Token管理**：使用LSP工具时注意控制查询频率，避免过多的LSP请求消耗资源
- 如果LSP工具不可用，记录警告并继续使用模式匹配方式

#### 2.4. [ ] 模式匹配

- 🔴 **限制文件读取**：如果目标文件很大，只读取目标文件中接口定义及其上下文（上下各50行）
- 根据接口模式特征匹配代码模式（如路由装饰器、注解等）
- 识别RESTful API端点、CLI命令处理函数、函数接口、注解和装饰器

#### 2.5. [ ] 业务语义提取

- 分析目标文件中的函数名、类名、注释，提取业务含义
- 分析目标文件中接口函数的参数和返回值，理解接口功能
- 结合目标文件的路径和模块名称，理解业务上下文
- 🔴 **优先从文档字符串和注释获取**：优先从文档字符串、注释和注解中获取信息，避免分析完整实现代码

### 3. [ ] 接口识别和分类

从步骤2的分析结果中，识别出目标文件中的所有接口，并对每个接口进行分类和特征提取。

**子任务Todo列表：**
- [ ] **3.1 接口候选识别**
- [ ] **3.2 接口分类**
- [ ] **3.3 业务语义优化**
- [ ] **3.4 接口特征提取**

#### 3.1. [ ] 接口候选识别

- 结合LSP识别出的符号和模式匹配找到的模式
- 参考Few-shot示例，判断目标文件中的哪些函数/方法符合接口定义
- 应用约束规则，过滤不符合条件的候选
- 将LSP识别结果与模式匹配结果交叉验证，优先采用LSP提供的精确位置信息

#### 3.2. [ ] 接口分类

- 根据接口类型列表，判断每个接口候选属于哪种类型
- 确定接口类型（RESTful API、CLI命令、函数接口等）

#### 3.3. [ ] 业务语义优化

- 从业务角度优化接口名称（不是纯技术函数名）
- 分析目标文件中接口函数周围的注释和文档字符串，提取业务含义
- 根据目标文件中接口函数的参数和返回值，推断业务功能
- 将技术性的函数名转换为更具业务语义的英文表达，如`create_node`、`deploy_component`等

#### 3.4. [ ] 接口特征提取

- 识别业务领域、业务功能
- 提取接口路径和方法（对于RESTful API，从路由注解提取）
- 提取参数信息（参数名、类型、是否必需、描述）
  - 🔴 **使用LSP工具**：使用LSP工具精准获取类型信息，避免读取完整函数体
- 提取返回值信息（返回类型、描述）
  - 🔴 **使用LSP工具**：使用LSP工具精准获取类型信息，避免读取完整函数体
- 识别相关注解和标签，确定代码层级

### 4. [ ] 生成接口对象

将从目标文件中识别出的所有接口，转换为符合输出格式的接口对象。

**接口对象字段：**
- **name**: 接口名称（技术名称，如函数名）
- **business_name**: 业务名称（业务语义化的名称，中文）
- **business_domain**: 业务领域（如"用户管理"、"订单处理"等）
- **business_function**: 业务功能（如"查询用户信息"、"创建订单"等）
- **interface_type**: 接口类型（从interface_types中匹配）
- **source_file**: 源文件路径（当前文件路径）
- **path_method**: 接口路径和方法（对于RESTful API）或函数标识（对于函数接口）
- **parameters**: 参数列表（参数名、类型、是否必需、描述）
- **returns**: 返回值信息（返回类型、描述）
- **description**: 接口描述
- **module**: 模块名称
- **layer**: 代码层级
- **language**: 编程语言
- **confidence**: 识别置信度（0.0-1.0）
- **tags**: 标签列表
- **annotations**: 注解列表（如`@GetMapping`、`@ApiOperation`等）

**质量保证**：
- 验证生成的接口对象结构完整性
- 确保所有必需字段都有值（如果无法确定某个字段的值，应使用合理的默认值）
- 验证接口类型在允许的类型列表中
- 确保置信度在合理范围内（0.0-1.0）

### 5. [ ] 写入输出文件

🔴 **强制要求**：将目标文件中识别到的所有接口写入`output_file`指定的临时文件。

- **确保输出目录存在**：如果输出文件的目录不存在，必须创建目录
- **写入JSON文件**：将接口数组序列化为JSON格式，写入到`output_file`
  - 使用UTF-8编码，JSON格式，缩进2个空格
  - 如果识别到0个接口，写入空数组 `[]`
- **验证文件写入成功**：确保文件写入成功后再返回状态
- **错误处理**：如果文件写入失败，返回 `{"ok": false, "error": "文件写入失败"}`
- 🔴 **强制要求**：所有错误情况都必须写入输出文件（即使是空数组），确保SubAgent可以读取文件判断处理状态

### 6. [ ] 返回执行结果

🔴 **强制要求：返回极简JSON格式**：Skill执行完成后，向SubAgent返回极简状态JSON，不包含接口数据。

**成功时**：
```json
{"ok": true, "count": 5}
```

**失败时**：
```json
{"ok": false, "error": "文件读取失败"}
```

**注意**：
- 如果文件中没有识别到接口，写入空数组 `[]`，返回 `{"ok": true, "count": 0}`
- `count` 字段表示识别到的接口数量
- 禁止返回详细的接口数据、文件内容或分析过程的详细信息

## 附加要求

- **LSP工具优先**：在支持LSP的语言中（Python、JavaScript/TypeScript、Java、Go、C/C++等），优先使用LSP工具获取结构化信息，无法使用时回退到模式匹配
- **Token管理**：
  - 处理目标文件前必须检查当前上下文大小，如超过10万tokens则强制清空（步骤2.1）
  - 处理目标文件完成后必须检查当前上下文大小，如超过15万tokens则报错（步骤6返回前）
  - 使用LSP工具时注意控制查询频率，避免过多的LSP请求消耗资源
  - 处理完目标文件后立即清理上下文，防止Token累积
- **文件读取限制**：如果目标文件很大，只读取目标文件中接口定义及其上下文（上下各50行）
- **错误处理**：
  - 目标文件不存在或无法读取：写入空数组 `[]` 到输出文件，返回错误JSON
  - 规则文件缺失：使用默认规则继续处理，但记录警告
  - LSP工具不可用：自动回退到模式匹配方式，记录警告但继续处理
  - 文件写入失败：返回 `{"ok": false, "error": "文件写入失败"}`
  - 所有错误情况都必须写入输出文件（即使是空数组），确保SubAgent可以读取文件判断处理状态
- **职责边界**：Skill只负责写入接口数组并返回极简JSON，接口ID以及批次/全局状态由调用方统一管理
