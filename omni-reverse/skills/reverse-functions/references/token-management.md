# Token 管理

## 预算（整个 Skill 全局有效）

- SKILL.md 正文目标 ≤300 行，references/ 单次读取 ≤1000 tokens
- 阶段间切换必须清空上一阶段中间信息，只保留缓存路径和状态
- Token 超限判断标准：上下文超 10 万 tokens 强制清空，单批次预估超 15 万 tokens 必须分批

## 概述
本 Skill 的 4 个阶段涉及大量 AI 分析和子 Agent 调用，需要统一的 Token 预算管理策略。

## 各阶段预算分配

| 阶段 | 主要工作 | 预估 Token |
|------|----------|------------|
| 阶段0 | 缓存检查 | < 1K |
| 阶段1 | 入口点识别（子 Agent） | 50-150K/批次 |
| 阶段2 | 场景识别（子 Agent） | 50-150K/批次 |
| 阶段3 | 功能划分（子 Agent） | 50-150K/批次 |
| 阶段4 | 文档生成（子 Agent） | 30-100K/批次 |

## 上下文管理策略

- **每阶段开始前**：检查上下文大小，超过 100K tokens 则强制清空
- **每轮子 Agent 完成后**：执行 /compact 压缩上下文
- **阶段切换时**：清空上一阶段中间信息，只保留缓存路径和状态
- **批次数限制**：每个批次预计 Token 消耗不超过 150K tokens
