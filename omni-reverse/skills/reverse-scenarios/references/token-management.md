## 概述

本文件定义场景反构各阶段的 Token 预算分配、上下文清理策略与阶段间数据传递优化规范。

## Token 预算分配

场景反构全流程 Token 预算建议如下：

| 阶段 | 主要任务 | 建议预算 | 说明 |
|------|----------|----------|------|
| 阶段0 | 缓存状态检查 | 1K | 读取状态文件，极少Token消耗 |
| 阶段1 | 场景模式识别与Few-shot生成 | 50K | AI分析代码库模式、生成示例 |
| 阶段2 | 场景清单构建 | 100K | 扫描代码库、识别场景、批次处理 |
| 阶段3 | 单场景文档生成 | 150K | 子Agent生成各场景文档 |

**总预算**：约 300K tokens

> 注：预算为建议值，实际消耗取决于代码库规模与场景复杂度。

## 阶段级 Token 控制

### 阶段1 Token 控制

- **入场检查**：阶段开始前检查上下文大小，如超过 100K tokens 则强制清空
- **输出精简**：只输出模式特征和统计信息，避免冗余描述
- **结果保存**：
  - 场景模式特征保存到 `scenario-patterns.json`
  - Few-shot示例保存到 `few-shot-examples.json`
  - 保存后强制清空上下文，只保留阶段名称和缓存目录路径
- **确认前检查**：用户确认前检查上下文大小，如超过 150K tokens 则强制清空后再保存

### 阶段2 Token 控制

- **入场检查**：阶段开始前检查上下文大小，如超过 100K tokens 则强制清空
- **批次处理**：
  - 超过 20 个文件时自动分批
  - 每批处理前后清理上下文
  - 单批场景数量控制在 5-10 个
- **输出精简**：只输出清单摘要和统计信息
- **中间结果**：通过 `scenario-list-batch-*.json` 文件传递各批次结果，主Agent不保留完整上下文

### 阶段3 Token 控制

- **入场检查**：阶段开始前检查上下文大小，如超过 100K tokens 则强制清空
- **批次处理**：
  - 场景数 ≤ 5：单批处理
  - 场景数 > 5：按每批 5 个场景分批
  - 每批处理前后清理上下文，只保留批次号和输出目录等必要信息
- **输出精简**：只输出生成进度和统计信息

## 上下文清理时机

| 时机 | 清理内容 | 保留内容 |
|------|----------|----------|
| 阶段开始前 | 上一阶段残留上下文 | 阶段名称、缓存目录、状态文件路径 |
| 批次处理前 | 前批次的场景详情上下文 | 批次号、输出目录、状态文件路径 |
| 阶段/批次完成后 | 当前阶段/批次的详细上下文 | 最终结果文件路径、统计摘要 |
| 用户确认前 | 所有非必要上下文 | 缓存文件路径、确认结果 |

## 阶段间数据传递

场景反构通过缓存文件在各阶段间传递数据，避免重复加载：

```
阶段1 输出：
  - .cache/reverse/scenarios/scenario-patterns.json
  - .cache/reverse/scenarios/few-shot-examples.json
  - .cache/reverse/scenarios/scenario-types.json
  - .cache/reverse/scenarios/constraints.json

阶段2 输入/输出：
  - 读取阶段1输出文件
  - 输出：.cache/reverse/scenarios/scenario-list.json

阶段3 输入/输出：
  - 读取：.cache/reverse/scenarios/scenario-list.json
  - 输出：omni-doc/specs/scenarios/SCN-XXX-*.md
```

**传递原则**：
- 只传递文件路径，不传递完整内容
- 各阶段按需读取所需字段，避免一次性加载整个文件
- 大文件（如场景清单）只读取前若干条用于展示

## 大文件处理

对于体量较大的 JSON/Markdown 文件：

- AI Agent 仅按需读取部分内容（如前若干条场景）
- 在批量展示或分析前，先评估文件大小和预估 Token 消耗
- 使用分页或分批方式处理，避免一次性加载

## 缓存复用

各阶段开始前检查缓存状态：

1. 读取 `.cache/reverse/scenarios/.cache-status.json`
2. 检查对应阶段的 `confirmed` 字段
3. 如已确认且产物文件存在：跳过该阶段，使用缓存
4. 如未确认或文件缺失：正常执行

**缓存清理**：
- 支持通过 `--clear-cache` 参数整体清理
- 或使用单独清理脚本删除缓存文件

## 异常处理与 Token 保护

- **强制检查点**：每个阶段的关键节点强制检查上下文大小
- **分级保护**：
  - 警告线（100K tokens）：提示即将清理
  - 强制线（150K tokens）：立即清空非必要上下文
- **优雅降级**：如 Token 接近预算上限，使用更简洁的输出格式
