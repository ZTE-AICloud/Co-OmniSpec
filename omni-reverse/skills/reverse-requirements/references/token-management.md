# Token 管理

本技能以 AI Agent 操作为核心，Token 消耗主要来自场景文档读取、需求分析和生成过程。合理的 Token 管理可确保流程顺利执行。

## Token 消耗分析

### 阶段级 Token 预算（估算）

| 阶段 | 主要操作 | 预估 Token |
|------|----------|------------|
| 阶段0：缓存检查 | 目录扫描、缓存读取 | 1-3K |
| 阶段1：需求分析 | 读取场景文档（每文件约5-20K）、EARS 转化 | 10-50K/场景数 |
| 阶段2：需求拆分 | 读取需求设计文档、EARS 展开、生成需求文件 | 5-15K/需求数 |

### 总预算建议

- **小规模**（<10个场景）：总预算 50-100K tokens
- **中规模**（10-50个场景）：总预算 100-300K tokens
- **大规模**（>50个场景）：总预算 300K+ tokens，建议分批处理

## 上下文压缩策略

### 阶段间上下文清理

- **阶段0→阶段1**：清理阶段0的目录扫描日志，仅保留场景文件路径列表
- **阶段1→阶段2**：压缩场景分析详情，仅保留「功能需求」章节内容到需求设计文档
- **阶段2完成后**：可选执行 `/compact` 压缩上下文，保留输出摘要

### 场景文档处理策略

- **分批读取**：超过 20 个场景文档时，建议分批读取处理
  - 每批读取 10-15 个场景文档
  - 每批完成 EARS 转化后写入需求设计文档
  - 再读取下一批
- **跳过已处理**：缓存中已确认的场景可跳过，仅处理新增/修改的场景

### 需求文件生成策略

- **逐条生成**：每个需求单独生成并写入文件，避免内存积累
- **批量写入**：生成 5-10 个需求后统一写入，减少上下文占用
- **即时释放**：生成完每个需求后，释放对应的中间变量

## 阶段间数据传递优化

### 文件路径传递

使用文件路径而非内容传递阶段间数据：
- 阶段1 输出：需求设计文档路径（`{REQUIREMENTS_CACHE_DIR}/internal/需求设计.md`）
- 阶段2 输出：需求文件输出目录（`{REQUIREMENTS_OUTPUT_DIR}/`）

### 状态文件传递

通过 `.cache-status.json` 传递执行状态：
- `progress` 字段标记阶段完成状态
- `timestamp` 字段记录执行时间
- `confirmed` 字段标记用户确认状态

### 大文件处理

- 超过 50KB 的场景文档单独处理
- 超过 100KB 的需求设计文档分章节读取
- 使用 Glob/Read 工具按需读取，避免全量加载

## 性能优化建议

1. **预检查**：阶段0 先检查缓存状态，对已完成阶段直接跳过
2. **增量处理**：利用 `--clear-cache` 控制是否全量重跑，避免重复处理
3. **并行读取**：场景文档可并行读取（Read 工具支持并发），但 EARS 转化需串行
4. **及时写入**：中间结果及时写入文件而非全部保留在内存

## 异常情况 Token 保护

- 单阶段 Token 消耗超过预估 50% 时，记录警告日志并继续执行
- 单阶段 Token 消耗超过预估 100% 时，中止阶段并提示用户
- 上下文窗口接近上限时，触发 `/compact` 压缩并记录检查点
