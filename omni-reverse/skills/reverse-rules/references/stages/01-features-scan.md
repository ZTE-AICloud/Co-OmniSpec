# 特征检测

<!-- 阶段1：特征检测 -->

## 职责

作为“代码特征分析专家”，对当前代码库进行全面特征检测，为后续规则映射与规则生成提供准确的基础信息。只报告代码中实际存在的特征，不推测或假设不存在的功能。

## 执行流程

### 0. [ ] 创建阶段1 子任务 Todo 列表

1. **步骤1** 清理上一阶段上下文，保证本阶段上下文干净
2. **步骤2** 检查缓存状态，确定是否需要执行
3. **步骤3** 获取仓库根目录与缓存目录
4. **步骤4** 执行特征检测（扫描构建文件、配置、源码结构）
5. **步骤5** 保存特征报告并展示，等待用户确认
6. **步骤6** 处理用户确认，更新缓存状态

### 1. [x] 清理上一阶段上下文

- 阶段开始时明确说明：“开始阶段1：特征检测。已清空上一阶段的上下文。”
- 输出精简，只保留检测结果与统计信息。

### 2. [ ] 检查缓存状态

- 读取：`{REPO_ROOT}/.cache/reverse/rules/.cache-status.json`
- 若 `features_scan.confirmed == true` 且**本次未请求重录**（例如未显式使用 `--clear-cache` 且用户未在对话中要求重新执行）：跳过阶段1，直接使用已有 `01-features.md`
- 若为 `false` 或不存在，或本次明确请求重录：执行阶段1，并覆盖旧结果

### 3. [ ] 获取仓库根目录与缓存目录

- 跨平台获取 REPO_ROOT（如调用 check-prerequisites 脚本）
- 缓存目录：`{REPO_ROOT}/.cache/reverse/rules/`
- 确保目录存在：`mkdir -p {REPO_ROOT}/.cache/reverse/rules`

### 4. [ ] 执行特征检测

#### 检测范围（参考 flow-formal-spec rules/1.features-scan）

- **项目基础信息**：项目类型、主要语言、代码规模、构建系统
- **技术栈**：框架与库、数据存储、通信机制、前端技术（如适用）、云原生、API 规范、代码质量、微服务治理
- **架构模式**：整体架构、设计模式、状态管理
- **工程化**：配置管理、日志、监控与指标、测试、CI/CD
- **领域与特殊技术**：电信/金融/游戏/物联网/AI/区块链等；DSL、代码生成、插件、多语言集成等

#### 检测策略

- 优先扫描：构建文件（package.json、pom.xml、CMakeLists.txt、Cargo.toml 等）、配置目录、源码结构、脚本与文档
- 代码内容：导入/依赖、核心类/函数、接口定义、配置与日志、错误处理
- 量化：规模分级（微型～超大型）、复杂度指标（目录深度、依赖数、配置数等）

#### 约束

- 所有结论需有代码证据，不确定处标注“需进一步确认”
- 在用户指定路径范围内扫描（若用户指定了 `--path`）

### 5. [ ] 保存特征报告并展示

- 将检测结果保存到：`{REPO_ROOT}/.cache/reverse/rules/01-features.md`
- 若目录不存在，先创建目录
- 输出格式：Markdown，包含“代码库特征检测报告”标题，以及项目概况、构建系统、技术栈分析、架构特征、工程化水平、领域特殊性、复杂度分布、建议关注重点、检测覆盖度说明等（结构可参考 flow-formal-spec 中 1.features-scan.md 的输出格式要求）
- 读取状态文件，将 `features_scan` 置为 `confirmed: false`、`progress: "completed"` 及当前时间戳，写回 `.cache-status.json`
- **交互模式**：向用户展示报告摘要（项目类型、主要语言、规模、关键技术栈、建议关注重点），并询问：“特征检测已完成，是否确认结果？[Y/n]”，根据用户响应决定是否继续；用户响应后再次读取状态文件，确认更新成功
- **全自动模式（`--non-interactive` / `--yes`）**：不再询问用户，直接视为已确认，进入下一步骤

### 6. [ ] 处理用户确认，更新缓存状态

#### 用户确认（交互模式下 Y/yes/回车，或全自动模式）

- 更新 `features_scan`：`confirmed: true`，当前时间戳，写回 `.cache-status.json`
- 说明阶段1 已完成，清空本阶段冗余上下文，自动进入阶段2

#### 用户拒绝（n/no）

- 允许查看详情、重新执行或手动修改 01-features.md

## 输出

- 特征报告：`{REPO_ROOT}/.cache/reverse/rules/01-features.md`
- 状态更新：`.cache-status.json` 中 `features_scan`

## 注意事项

- AI Agent 必须在阶段1 完成后暂停，等待用户确认后再进入阶段2
- 特征报告是阶段2 规则映射的输入，必须确认后再使用
- 跨平台：所有脚本调用需同时支持 Linux (Bash) 与 Windows (PowerShell)
