# 用户规则注入

<!-- 阶段4：用户规则注入（可选） -->

## 职责

将用户自定义规则文件注入到 `omni-doc/rules/` 目录；可选地调用大模型进行规则整合与去重，与已生成的规则融合。本阶段为可选，失败不阻塞主流程。

## 执行流程

### 0. [ ] 创建阶段4 子任务 Todo 列表

1. **步骤1** 清理上一阶段冗余上下文
2. **步骤2** 检查是否存在用户规则文件
3. **步骤3** 若存在则执行注入（与可选智能融合）
4. **步骤4** 更新缓存状态并结束

### 1. [x] 清理上一阶段冗余上下文

- 说明：“开始阶段4：用户规则注入。已清空上一阶段的冗余上下文。”

### 2. [ ] 检查用户规则文件

- 用户规则文件路径（二选一或按项目约定）：
  - `{REPO_ROOT}/.cache/user_input/user_rules.md`
  - 或 `{REPO_ROOT}/.omni-infra/user_rules.md`
- 若不存在：跳过阶段4，将 `user_rules_injection` 标记为已跳过或 completed，结束规则反构流程
- 若存在：继续步骤3

### 3. [ ] 执行用户规则注入

#### 注入方式

- 将用户规则内容写入或合并到 `{REPO_ROOT}/omni-doc/rules/` 下指定文件（如单独章节或合并到已有规则）
- 具体策略可与 flow-formal-spec 一致：先写入/追加，再可选调用“规则整合”脚本或 Agent，处理冲突与重复

#### 可选：智能融合

- 若项目提供或约定“规则整合”脚本（如 user_rules_optimizer）：在注入后调用，对 `omni-doc/rules/` 进行整合与去重
- 若未提供或用户未启用：仅做注入，不调用大模型或脚本

#### 失败处理

- 注入或融合失败时：记录警告，不退出整体流程；保留已生成的规则文档

### 4. [ ] 更新缓存状态并结束

- 更新 `.cache-status.json` 中 `user_rules_injection`：`confirmed: true` 或 `skipped: true`，及时间戳
- **交互模式**：向用户简要说明是否执行了注入、是否执行了智能融合、结果路径
- **全自动模式（`--non-interactive` / `--yes`）**：不再额外询问用户，直接结束规则反构流程
- 规则反构流程结束

## 输出

- 更新后的 `{REPO_ROOT}/omni-doc/rules/` 下的规则文件（若有注入或融合）
- `.cache-status.json` 中 `user_rules_injection`

## 注意事项

- 本阶段为可选；无用户规则文件时直接结束
- 跨平台：若调用脚本，需同时支持 Linux 与 Windows
